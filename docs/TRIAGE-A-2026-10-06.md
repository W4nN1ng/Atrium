### 判据（`sameProductTwoForms()`，`src/main/library/regroup.ts`）

```
乙类（保持）—— 归档侧那行的 library_path **就是那个同名目录**，source_path 才指向压缩包：
  library_path = E:\vrc\A\贴图\皮肤\Sexy skin material for VRC 6053463
```

## 六、收件箱持久化（甲轨 ④，本次完成）

### 问题

`startIngest()` 里的 `jobs` 是一个**内存态 `Map`**，进程一退全丢。真机表现：
拖进 20 个包、指纹跑完 12 个正等你确认，这时重启程序 —— 那 12 张卡**凭空消失**，得重新拖一遍。

### 做法：持久化**源路径**，启动后重新入队

`%APPDATA%\A\inbox.json`：

```json
{ "version": 1, "items": [{ "path": "E:\\vrc\\A\\x.zip", "at": 1759700000000 }] }
```

**刻意不存 `WorkerResult`，也不存密码。** 三个理由：

1. **worker 结果是纯函数产物**：`(源路径, 设置, 词典, 已学规则) → WorkerResult`。
   磁盘上那份文件没动过，所以启动后重跑一遍得到同一份结果。走这条路等于白捡
   「用户点重试」已有的全部正确性，且**不新增表、不动 schema、不碰真库**。
2. **staging 目录本来就不跨重启** —— `pruneStaging()` 启动即清空整个 `staging/`，
   所以 `res.stagingPath` 存了也没用，解压产物必须重做。
3. **密码不持久化**：`api.ts` 里压根没有 `password_vault` 的调用，密码只在会话内有效。
   重启后重问一次既简单又更安全。

启动后 3 秒（避开"启动到可用 ≤2 秒"）、逐条错开 300 ms 调 `restoreQueue()`，并广播
`ingest:restored` 让界面报一句 toast —— 不提示的话用户会以为队列里凭空多了东西。

### 阶段策略（`src/main/ingest/queuePolicy.ts`）

| 阶段 | 动作 | 理由 |
|---|---|---|
| `awaiting_confirm` / `duplicate` / `failed` | **落盘** | 在等人处理。`failed` 也存：用户可能正看着报错决定要不要修 |
| `done` / `cancelled` | **划掉** | 已有结论；用户自己取消的不该重启后又冒出来 |
| queued / hashing / … / committing | 不动 | 正在跑的中间态。恢复它等于从 `queued` 重跑，跑完自然会落盘 |

只在**阶段真的变化**时写盘（`job.persistedStage` 比对）—— `update()` 在指纹进度里每几毫秒被调一次，
无条件写会把磁盘打满。

### 顺带修掉的坑：`ELECTRON_RUN_AS_NODE`

`npm run dev` 本来**起不来**，报一句极具误导性的错：

```
TypeError: Cannot read properties of undefined (reading 'isPackaged')
    at Object.<anonymous> (out/main/index.js:...)
    at Module._compile ...
```

看着像 bundle 坏了或 `electron-vite` 配错，其实什么都没坏：这个环境变量一旦是 `1`，
electron.exe 会把主进程当**普通 Node 脚本**跑，`require('electron')` 返回的**不是 API 对象，

实测：故意 `set ELECTRON_RUN_AS_NODE=1` 之后 `npm run dev:debug` 照样起得来。

> ⚠ 另外记一条：跑过 `dev` 之后 `better_sqlite3.node` 是 Electron ABI(130)，
> 直接 `node tools/xxx.cjs` 会报 `NODE_MODULE_VERSION 130 … requires 137`。
> **这是设计如此**（README 有写），先 `npm run native:node` 切回来即可。
