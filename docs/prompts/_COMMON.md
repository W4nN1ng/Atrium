# VPM 任务共同规则（每个任务卡都适用）

> 这份文件不重复功能细节；只写**所有任务都必须遵守的边界、质量闸门和交接格式**。
> 开工前先读：`AGENTS.md` → 本文件 → `docs/VPM-ARCHITECTURE.md` 的相关章节 → 任务卡。

---

## 1. 一次只做一张卡

- 一张任务卡 = 一个分支 = 一个 PR。
- 不顺手重构、不顺手加功能、不顺手改文案；发现需要，写成新任务。
- 目标 ≤ 15 个文件、≤ 500 行非测试代码；超过就停下拆卡。
- 只读任务卡列出的文档章节；不要通读 P0–P9 全部提示词。

---

任务卡里出现的代码路径（如 `install/journal.ts`）默认相对**仓库根**；
文档路径（如 `VPM-ARCHITECTURE.md`）默认相对 `docs/`。不确定时按任务卡开头的相对链接找。

## 2. 硬约束（任何任务都不能破）

1. **净室**：不复制 ALCOM/vrc-get 的代码、注释、测试、文案、图标、模板、资产。
   只依据行为规格、公开协议和 Atrium 自己的代码。见 `docs/VPM-CLEANROOM.md`。
2. **核心库不动**：不修改 `library.db` 的 schema、`SCHEMA_VERSION`（11）、迁移。
3. **非 C 数据**：VPM 的缓存/回滚仓/备份只能在非 C 数据根；没有合法数据根就不启用。
4. **不永久删用户文件**：旧包/旧资源进 vault；缓存/临时文件除外，但要有边界。
5. **不手写 `.meta`**：unitypackage/模板里的 `.meta` 原样搬运。
6. **不写 VCC**：`settings.json` 和 `vcc.liteDb` 只读；不写扩展字段。
7. **联网默认开启、可关闭**：用户可在仓库区关掉；关闭后任何 HTTP 都不能出站；没有遥测/崩溃上报。
8. **主进程不返回 UI 句子**：只返回错误码 + 参数，渲染层走三语 i18n。
9. **工程写入只走事务与闸门**：`Packages/`、manifest 归 VPM 事务；`Assets/` 素材导入归现有桥接；
   `Packages/com.avca.bridge` 归核心桥接安装器。任何维护动作（备份/复制/迁移/换版本）
   先检查 Unity 与素材写入活动（导入/撤销/删除 GUID/成员导入）；
   素材写入和包事务不能同时写同一工程。
10. **不发布**：P0–P8 不创建 GitHub Release；P9-E 按任务卡执行。
11. **素材联动是硬需求**：Atrium 启动/打开工程后，该工程立即成为当前导入目标；
    双击素材导入这个工程。VPM 只通过核心注入的窄回调绑定目标，
    不维护第二份“当前工程”，也不直接调用桥接。
12. **不误删导入资产**：VPM 清理旧 Assets 只按包声明的 GUID/路径白名单，
    不做整目录扫荡；与 `import_log`、桥接包或未知文件重叠时保留并报告。

---

## 3. 架构规则（详见 `docs/VPM-ARCHITECTURE.md`）

- 依赖方向：`renderer → preload/DTO → main/ipc → 应用服务 → 纯领域/端口 → 适配器`；
  不允许反向 import，不允许跨层直接读 DB/写文件/发网络。
- 跨模块只 import 对方 `index.ts`；不 import 其他模块的 `internal/`。
- 组合根只有 `src/main/vpm/index.ts`；其他文件不 new 跨模块服务。
- 一个数据/路径只有一个写入者；写前备份，先临时后原子。
- 当前工程/导入目标只有核心一份状态；VPM 只能通过 gate 注入的端口读取或请求绑定。
- 素材导入、包事务、备份/迁移/换版本共用工程活动闸门；不能靠“应该不会同时发生”。
- 纯领域（`shared/vpm/domain/`）不碰 Electron、`node:fs`、SQLite、HTTP。
- 复杂模块必须有 `README.md`：职责、非职责、公开 API、数据、失败模式、测试入口。
- 新增端口/接口只在需要 fake 或跨模块时引入；不为"架构好看"加空转发层。

---

## 4. 质量闸门

按任务类型执行，任务卡会写明哪些必须跑：

```powershell
npm test                 # 全量；真实退出码必须 0
npm run typecheck        # 退出码 0
npm run build:dir        # 涉及主进程/渲染产物时
node tools/check-vpm-taskpack.cjs   # 改了任务卡/任务板/对账表时
```

- 测试数字以实际为准；不硬编码旧基线。
- 新逻辑必须有能"改回去就变红"的测试。
- 失败注入：事务每一步都要有失败用例；不是只看 happy path。
- 涉及 UI：走真实路径（真点击/真滚动/首次触发），并留截图。
- 涉及工程文件：在沙盒里用真 Unity 2022.3.22f1 复测；假对端不算。
- 未验证项写"未验证"，不写"应该可以"。

---

## 5. 沙盒规则

- `AVCA_APP_HOME` 必须含 `avca` 或 `sandbox`，并设 `AVCA_REQUIRE_SANDBOX_HOME=1`。
- 数据根放沙盒非 C 目录；工程放沙盒目录。
- 绝不用 `E:\vrc\A`、`E:\Atriumdate`、`%APPDATA%\A\library.db` 做实验。
- Unity 用 2022.3.22f1；关闭 Unity 再改包；不要 `taskkill /F /IM Unity.exe`，按 PID。
- 不跑真实发布/不建 Release（P9-E 除外）。

---

## 6. 错误与 i18n

- 新错误码先在 `shared/vpm/errors.ts` 登记，再在三份 i18n 里补齐。
- 错误码按域前缀，避免一个 `vpmFailed` 打天下。
- 主进程日志可以写英文/中文诊断，但不把原始请求头/token/用户文件内容写进去。
- UI 文案不承诺未实现的能力；不写"即将支持/敬请期待"。

---

## 7. 文档与交接

每个任务完成时必须：

1. 更新自己模块的 `README.md`（如有）；
2. 更新 `docs/VPM-TASKS.md` 的状态；
3. 在 PR 里写固定交接段：

```text
Task: P?-?
状态: 完成 / 部分 / 阻塞
公开 API/契约变化: ...
新增/修改模块 README: ...
已验证: ...
未验证: ...
给下一个任务: ...
```

没有交接段的 PR 不算完成。

---

## 8. 停止规则

遇到下面任一情况，**停下报告**，不要猜、不要绕过：

- 需要改核心 `library.db` schema/迁移；
- 需要把缓存/数据根放 C；
- 需要写 VCC 数据；
- 需要复制 ALCOM 代码/文案/资产；
- 事务失败无法安全回滚；
- 任务范围超出 15 文件/500 行，或需要跨 3 个以上模块；
- 阶段门禁未过就想开下一阶段；
- 真实用户数据/工程可能被影响。

---

## 9. 分支与 PR

- 从最新 `main` 开 `codex/vpm-<task-id>-<slug>`。
- 不直推 `main`；PR 目标 `main`。
- PR 标题：`feat(vpm-<task>): ...` / `fix(vpm-<task>): ...` / `docs(vpm): ...`。
- PR 描述：任务 ID、改了什么/没改什么、测试数字、截图、未验证、净室检查、交接段。
- 验证通过后按 `AGENTS.md` 合并；合并后如果是产品代码变化，更新本机安装版。
