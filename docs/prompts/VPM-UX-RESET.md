# VPM-UX-RESET · 界面与启动体验重置（取代旧卡里的 UI 要求）

> 写于 2026-10-22，作者：实现方。状态：**待用户确认**（确认后按 §7 的顺序施工）。
>
> 这份文件**取代**以下卡里的 UI 部分（实现细节以本文件为准，那些卡只保留服务层要求）：
> `P5-D`（新建/打开 Unity UI）、`P6-D`（维护 UI）、`P7-A`/`P7-B`（仓库治理 UI）、
> `P2-D`（工程页信息密度）。
>
> 一句话：**用户只需要两件事——把素材导进来、把工程打开。其他都不该占屏幕。**

---

## 1. 设计原则（以后所有界面都按这四条判）

1. **一屏只说一件事**：项目列表页只放项目；素材页只放素材。不混排、不解释。
2. **状态用眼睛看，不用读字**：运行中 = 一个绿点 + 按钮变"已打开"，不写"Unity 未打开"。
3. **一句话能说清的不写两句**：空状态最多一行字 + 一个按钮；删掉所有"为什么/背景/科普"。
4. **主按钮唯一**：每屏一个实心按钮；其余全是文字按钮或图标。

## 2. 六个问题的根因与修法

### 2.1 新建的工程打不开 Unity（必须先去 Hub 才行）

**实测事实**（2026-10-22 21:00 用户机器）：

- `Unity.exe` 进程在跑（PID 40652），但 `MainWindowHandle = 0`（没有窗口）；
- 工程目录里**没有 `Temp`、没有 `Library`**（Unity 从没开始打开工程）；
- `%LOCALAPPDATA%\Unity\Editor\Editor.log` 里没有这次启动的记录；
- 同一个工程用 **Unity Hub 打开是正常的**。

**根因**：直接 `spawn("…\Unity.exe", ["-projectPath", path])` 绕过了 Hub。Unity 2022.3 在
"没走 Hub / 没拿到许可上下文"时会**在创建窗口之前**停住，看起来就是"进程在、窗口没有"。

**修法（R1）**：

1. **启动策略改为「Hub 优先」**：
   - 有 Hub → 用协议打开：`unityhub://<version>/<url-encoded 绝对路径>`
     （经 `shell.openExternal`，不拼 shell 命令）；
   - 没有 Hub / 协议失败 → 回退 `Unity.exe -projectPath`（保留现有参数数组方式）。
   - 编辑器仍然必须已安装且版本匹配；找不到报 `vpmUnityNotFound`。
2. **启动要验证，不能只看 spawn 成功**：spawn 之后轮询 `Temp/UnityLockfile` 或
   `Library/` 出现（每 1s，最多 90s）。
   - 90s 内出现 → 状态"启动中"→ 等桥接心跳 → "已打开"；
   - 90s 没出现 → 明确失败：`Unity 没有打开这个工程`，给两个按钮
     「用 Hub 打开」「查看日志」，并**清除启动绑定**。
3. **顺序纠正**：启动是主动作，连接是后台结果。UI 主状态只用
   `未打开 / 启动中 / 已打开`，**不要**把"正在连接"当主状态显示。
4. 启动失败后**不要**把工程留在"导入目标"上。

### 2.2 立即备份没有反馈、找不到 zip

**根因**：`backup.create` 是同步长任务（收集 + 压缩），UI 只有一个按钮转圈；
成功提示在面板顶部（要滚上去才看得到），默认路径在 `<数据根>/backups/<工程>/`，用户不知道。

**修法（R2）**：

1. 点击后**立刻**在按钮下方出现一行进度：`正在收集… 3,214 个文件` →
   `正在压缩… 62%` → 完成。用现有 `onProgress`，不要新造。
2. 成功后**在按钮下方直接出现结果卡**（不是顶部）：
   `备份完成 · 1.24 GB · 14:32` + 主按钮 **「打开所在文件夹」**。
3. 失败：同一位置红色一行 + 原因 + 「重试」。
4. 备份记录列表每行显示**文件名**（不是只显示时间），点击文件名直接打开所在文件夹。
5. 记录默认只显示最近 3 条，多出来的折叠成「更多备份（N）」。

### 2.3 工程列表太乱、字小、信息多

**根因**：一行里塞了 路径/版本/未运行/Unity 未打开/导入历史/设为导入目标/高级连接选项，
还把"工程台账"和"新建工程"塞在同一个滚动区底部。

**修法（R3）**：改成 ALCOM 那种"一行一个工程、右侧固定三个动作"：

```
★  33                                  2022.3.22f1     [打开 Unity]  [管理]  [备份]  [⋯]
   E:\atriumproject\33                                ● 运行中
```

- 名称 **14px**，路径 11px 灰色；**不再显示**"未运行 / Unity 未打开"这类文字，
  运行中只用一个绿点 + 按钮文案变「已打开」。
- 右侧固定：**打开 Unity**（主）、**管理**（进详情）、**备份**、`⋯`（导入历史 / 设为导入目标 /
  打开文件夹 / 移除 / 高级连接）。
- 删除行内的「导入历史」「设为导入目标」「高级连接选项」三个常驻按钮（进 `⋯`）。
- 删除每行下方的 `Unity 未打开` 文案。

### 2.4 项目列表要放到最上面，一进来先看到项目

**修法（R4）**：

- 左侧导航第一项改为 **「项目」**（当前是"当前工程"且排在"设置"上面、在分类之后）。
- 启动后的**默认落地页 = 项目列表**（现在是素材库）。
- 导航顺序：`项目` → `素材`（收件箱/最近添加/全部素材/合集/分类…）→ `设置`。
- 项目列表页不再包含"新建工程"以上的任何说明文字；顶部只有一行：标题 + 「新建项目」。

### 2.5 "未匹配到集合"提示反复出现，删掉

**根因**：`RemergeNotice` 在检测到运行工程、但没匹配到集合时弹一条提示
（"检测到「33」· 没匹配到集合，视图没动" + 换个集合/这次忽略），每次切换都会重算。

**修法（R5）**：

- **删除这条提示与它的触发逻辑**（不是隐藏）。视图就是不动，用户不需要被通知"没动"。
- 连带删除设置里"打开 Unity 时自动切换集合"的相关开关（如果只有它一个消费方）。
- 保留的是"合集"本身：用户点进合集才切换。

### 2.6 拖放不能拖文件夹/压缩包；选择文件只能选一个 unitypackage

**根因（待确认，按此排查）**：

- 拖放走 `DropOverlay` → `window.a.system.pathForFile(file)`；文件夹在 `DataTransfer` 里
  未必有 `File` 条目，`paths` 为空 → 静默什么都不做。
- "添加素材"的 `pickFiles` 有的入口带了 `extensions: ['unitypackage']` + 默认单选。

**修法（R6）**：

1. 拖放：`DataTransfer.items` 里同时读 `getAsFile()` 与 `webkitGetAsEntry()`；
   文件夹按目录递归展开（主进程已有 `pickDirectory`/摄取队列支持目录）；
   接受 `.unitypackage / .zip / .rar / .7z / 文件夹`。
   拖不进任何东西时**必须**给一句"拖入的是文件夹还是文件？没识别到路径"。
2. 所有"选择素材"入口统一：`multiple: true`，过滤器
   `素材包 (*.unitypackage;*.zip;*.rar;*.7z)` + `所有文件 (*.*)`；
   旁边固定一个「选择文件夹」按钮（`pickDirectory`）。
3. 拖放与选择器最终都进同一个摄取队列，不再有第二条路径。

### 2.7 工程详情弹窗：七个按钮挤一行、概览塞满技术字段、框太小

**实测（截图 2026-10-22 21:43）**：

- 底部 footer **一排 7 个按钮**，宽度不够导致文字折行：`打开文件 夹`、`重新扫 描`、
  `查看变 更`、`从台账移 除`；
- 同一个 footer 里，有的按钮有描边、有的没有（`.btn` 与 `.btn-ghost` 混用）；
- 顶部"概览"是一张 6 行的表：工程目录 / Unity 版本 / 编辑器 / vpm-manifest 哈希 /
  上次扫描 / 状态（`运行中 · wmi`）——**全是排障信息**，字 11px；
- 整个弹窗宽约 520px，接近正方形，内容全挤在中间。

**修法（R8，与 R3 一起验收）**：

1. **尺寸**：宽 760–840px、高 80vh；内容区独立滚动，**footer 固定一行**。
2. **顶部只留**：项目名（18px）+ 版本徽标 + 运行状态（一个绿点）。
   **不放路径、不放哈希、不放"上次扫描"**。
3. **主体分三段**（分段标题，不是一张大表）：
   - **包**（默认）：已装/可更新 + 搜索 + 列表（沿用现状，删掉解释段落）；
   - **备份**：一个按钮 + 最近 3 条；
   - **高级**：默认**折叠收起**，里面才是路径 / 编辑器 / manifest 哈希 / 上次扫描。
4. **Footer 只留两个**：`打开 Unity`（实心主按钮）+ `关闭`（文字）。
   其余全部进右上角 `⋯`：打开文件夹 / 重新扫描 / 查看变更 / 从台账移除。
5. **按钮统一**：只有两种——`.btn`（无描边文字）和 `.btn-accent`（实心）；
   禁止第三种描边样式；所有按钮 `white-space: nowrap`，**不允许折行**；
   一行放不下就说明按钮该进 `⋯`。
6. 删除 `状态：运行中 · wmi` 里的 `· wmi`（技术实现不该给用户看）。

### 2.8 删掉所有"废话小字"

逐条删（**不是隐藏**）：

| 位置 | 要删的文案 |
|---|---|
| 侧栏合集空状态 | `还没有集合。打开 Unity 时它没地方可切——先按库里出现过的模型补建一批。` |

保留的唯一"说明"位置：**危险确认框**里的一句风险提示（删除/降级/换版本）。

### 2.10 详情标题重复（弹窗标题 = 正文第一行）

**实测（截图）**：弹窗标题是 `22`，正文第一行又是 `● 22  [2022.3.22f1]` —— 名字出现两次。

**修法（R10）**：**删掉正文里的名字**，弹窗标题保留项目名；正文第一行只留
`版本 + 运行点 + ⋯`（靠右）。这样名字只出现一次。

### 2.11 「当前工程」页整体换成「项目」页：删掉核心 Unity 工程面板

**实测（截图）**：页面顶部是核心的 Unity 工程列表（12 个，每行
`名称 / 路径 / 2022.3.22f1 / 未运行 / Unity 未打开 / 导入历史 / 设为导入目标 / 高级连接选项`），
而 VPM 的「项目与包」被挤到最下面。两套工程列表并存，用户不知道该看哪个。

**修法（R11）**：

1. **删除核心 Unity 工程面板**（`pages/Project.tsx` 里的工程行、顶部"刷新工程列表"
   工具条、底部"导入目标：未选择"状态条、每行的"设为导入目标 / 高级连接选项 / 卸载桥接"）。
   - **`导入历史` 保留**，但入口从行内按钮挪进项目行的 `⋯`（它记的是"哪些素材导进过这个
     工程"，跟 R11 要删的"两套工程列表"不是一回事）。
2. 该页内容**只有 VPM 项目列表**（R3 那一套），页面标题就叫「项目」。
3. 侧栏「当前工程」改名为「项目」，位置按 R4 置顶。
4. 桥接安装不再有 UI 入口：**启动工程时自动绑定导入目标 → 自动装桥接**；
   装失败在项目行上用一条红字说明（可点重试）。
5. 连接状态（心跳/锁文件）仍然在后台跑，只是不再有一整块 UI 展示；运行状态只用一个绿点。

**保留**：`UnityConnections`、`bridge` 安装逻辑、导入目标解析规则（后台不动）。

### 2.12 同时只能开一个工程：启动另一个就拒绝，并说明原因

**需求原话**："先不做两个项目启动时的切换导入目标按钮，用户启动另一个项目时直接拒绝启动，
并告知原因就好。"

**修法（R12）**：

1. 启动前检查：**任意** Unity 工程在运行（心跳 / 锁文件 / WMI 任一路命中）且不是目标工程
   → **拒绝启动**，错误码 `vpmUnityAlreadyRunning`，文案带上正在运行的工程名：
   > 已经有工程「33」在 Unity 里运行。请先关闭它，再打开「22」。
2. 拒绝时**不改**导入目标、不装桥接、不 spawn 进程。
3. 目标工程自己在跑 → 返回 `alreadyRunning`，把窗口提到前台（`focus`），不重复启动。
4. 删除「设为导入目标」按钮与其 UI（核心面板一起删掉，见 R11）；
   导入目标仍然由"启动即绑定"决定，规则不变：显式选择 > 启动绑定 > 单工程自动。
5. 用户从 Hub 手动开的工程：仍按"单工程自动"识别为目标（后台规则不变）。

### 2.13 行内 `⋯` 菜单被列表容器裁剪

**实测（2026-10-22 23:22）**：点项目行的 `⋯`，菜单出现在**项目框内部**，跟着列表一起滚动，
底部还被切掉一半。

**根因**：菜单用 `<details>` + `absolute`，而列表容器是 `overflow-y-auto` ——
绝对定位的子元素会被最近的滚动祖先裁剪。

**修法（R13）**：做一个统一的 `MenuButton`（`components/ui.tsx`）：
- 用 `createPortal` 渲染到 `document.body`，`position: fixed`，按锚点矩形定位；
- 空间不够时向上翻；右边界夹住视口；
- 点外面 / Esc / 滚动 / 改窗口大小都关闭；
- 项目行与工程详情统一用它，删掉各自的 `<details>` 实现。

### 2.14 新建工程选位置：选到"已经是工程"的目录要说人话

**实测（2026-10-22 23:22）**：用户同时装了 ALCOM 和 Atrium，ALCOM 的工程都在
`E://ALCOMProjects//<名字>`。在「新建工程 → 位置」里想选这个根目录，行为不友好。

**修法（R14）**：

1. **选到工程目录**（该目录里有 `ProjectSettings/ProjectVersion.txt`）→ **自动上移一级**
   并把提示写成一句话：`「22」是一个工程，已改用它的上级目录 E://ALCOMProjects`。
   **不要**直接报 `parentInsideProject` 让人猜。
2. **选到"装着很多工程的根目录"** → 允许（这是正常用法），提示语改成
   `工程会建在 E://ALCOMProjects//<名称>`，不吓唬人。
3. 目标已存在时才拒绝，文案给到具体路径：`E://ALCOMProjects//22 已存在，换个名字或位置`。
4. 目录选择器不再过滤/跳过任何目录（能进得去才选得到）。

### 2.15 添加已有工程：允许选"工程根目录"，自动扫描下一层

**修法（R15）**：

1. 「添加已有工程」支持选一个**根目录**：扫描它的**下一层**（不看更深），
   凡是有 `ProjectSettings/ProjectVersion.txt` 的都列出来。
2. 弹窗列出候选（名称 + 路径 + Unity 版本），默认全选，可以取消勾选；
   已在台账里的显示"已添加"且不可选。
3. 一次批量加入；单个失败不影响其它（逐条给结果）。
4. 选到的目录**本身**就是工程 → 直接加它，不进扫描流程。

### 2.16 删除工程：勾选"同时删除文件夹"→ 整个项目进回收站

**实测（2026-10-22 23:46）**：点「从台账移除」没反应（弹窗被套在详情弹窗里，详情关着就永远不显示）；
而且用户希望删除时能**连工程文件夹一起删**，但要走回收站。

**修法（R16）**：

1. 移除弹窗挪到**顶层**（不再嵌在详情弹窗里）。
2. 弹窗里加勾选：**「同时删除工程文件夹」**（默认不勾），下面一行小字
   `整个文件夹会移到回收站，随时可以还原`。
3. 勾了 → `vpm:project-trash`：`shell.trashItem(工程路径)` → 成功后从台账移除；
   没勾 → 只从台账移除（文件夹保留）。
4. **不提供永久删除**，也不弹"是否永久删除"——回收站就够了。

### 2.14 补充：数据根不能当工程位置

实测用户把 `E://ALCOMprojects`（正好是 VPM 数据根）选成"新建工程位置"，
被 `parentUnsafe` 拦下，但界面只显示 `{{reason}}` 原文。

- 错误参数现在会透传到渲染层（`key|{params}`），`errorText` 负责插值；
- 新建失败时把 reason 代码**逐条翻译**（`vpm.create.reason.<code>`），
  其中 `parentUnsafe` 明确写成"这个目录是 Atrium 的数据根（放备份/缓存的地方），
  不能在这里建工程"。

## 4. 验收标准（用户视角，逐条可点）

1. 打开应用 → **第一屏就是项目列表**，一行一个项目，字够大，右侧只有 3 个按钮。
2. 点「新建项目」→ 填名字 → 创建 → **自动打开 Unity**（走 Hub）→ 90s 内窗口出现。
3. 打开失败时，屏幕上有一句人话 + 「用 Hub 打开」按钮，不是无限转圈。
4. 点「备份」→ 立刻看到进度 → 完成卡片上有「打开所在文件夹」，一点就到 zip。
5. 拖一个**文件夹**、一个 **zip**、一个 **unitypackage** 到窗口 → 都进队列。
6. 「选择文件」能**多选**，且能选到 zip/rar/7z；旁边有「选择文件夹」。
7. 界面上**没有**"没匹配到集合"、没有"Unity 未打开"、没有"还没有集合…"。
8. 全程没有需要读超过一行的说明文字才能完成的操作。
9. 工程详情弹窗够大（**≥1000px 宽**）、footer **只有两个按钮**、没有任何按钮文字折行。
10. 「项目」页只有一套工程列表（VPM 的），**没有**第二套 Unity 工程列表、没有"导入目标"状态条。
11. 项目名 17px、路径 12px，肉眼一眼能读，不用凑近看。
12. 详情弹窗里项目名**只出现一次**。
13. 工程 A 在运行时点工程 B 的「打开」→ 明确提示"已经有工程「A」在运行，请先关闭"，
    不会静默失败、不会开出第二个 Unity。
