## 3.5 本阶段实现解剖（ALCOM → Atrium）

**ALCOM 的关键机制（行为观察）**

- Tauri command 是 UI 与后端的唯一通道；长任务用 channel 推进度，
  同时有明确的返回结果/错误结构；前端用 React Query 缓存项目/包/仓库数据，
  操作后失效/刷新。
- 页面按项目/包/模板/设置分块；包管理有选择、批量操作、变更确认。
- 更新器读**签名**更新清单并校验后安装，支持 stable/prerelease；
  日志有 GUI 日志、Unity 输出转发和错误本地化。

**Atrium 的独立实现**

- IPC 统一信封 `{ok, data | error}`，错误只回 code + 参数，主进程不回中文；
  长任务返回 `opId`，用进度事件 + **拉取式状态**双通道，刷新/漏事件后 UI 仍能恢复。
- UI 懒加载，不新增顶级导航；一个屏幕一个主按钮；抽屉 + 变更单；
  无永久批量条。VPM 状态放独立 store/hook，不污染核心素材页。
- 更新只做手动检查：GitHub Release → 下载 Setup → 从发布正文解析 SHA-256 →
  校验 → 用户点安装；不静默、不自动。检查可关。
- 日志/诊断：opId 关联、路径脱敏、token 脱敏、导出诊断包；错误 code + i18n key。
- 对账证据按 `VPM-PARITY.md` 逐行更新；未做/部分做如实标注，不用截图冒充完成。
- 不承诺 DOM 测试基础设施；用纯 reducer/wiring 测试 + 真机截图/交互清单。

**施工顺序**

1. IPC 契约/状态拉取/错误码统一。
2. 只读页面收口 + 截图。
3. 购物车/变更单/进度交互。
4. 操作记录/诊断导出。
5. 更新检查（受控）。
6. 清理用量显示；最后做对账与性能/键盘检查。

**最容易做错**

- 只发事件、不做拉取状态 → 漏一个事件 UI 永远转圈。
- 主进程回中文/原始 HTTP 正文 → i18n 与安全都坏。
- 静默自动更新 → 用户失去控制。
- 把 VPM 状态塞进核心 store → 停用 VPM 后核心行为改变。
- 为了"对齐 ALCOM"增加按钮/导航 → 违背轻量化目标。

**详细内容**：`docs/VPM-IMPLEMENTATION-GUIDE.md` §11。

## 4. UI 收口

### 4.1 逐屏检查

对以下屏幕做截图 + 交互清单：

- 项目列表（有/无工程、搜索、选中）
- 工程详情（概览/包/备份/操作记录）
- 包抽屉（空/有包/搜索无结果/筛选）
- 变更单（正常/冲突/缺失/磁盘不足/Unity 运行中）
- 执行进度（下载/解压/提交/完成/失败/取消）
- 设置 → 项目与包（仓库/模板/Unity/数据/高级）
- 新建工程（模板/路径/错误）
- 导入 VCC/导入模板/深链确认
- 安全模式/停用/回退页面

检查项：

1. 是否只有一个实心主按钮？
2. 是否出现永久批量条/工具栏？
3. 空状态是否只有一个动作？
4. 禁用按钮是否说明原因（tooltip/旁注），而不是灰着不说话？
5. 错误是否给 code/详情/重试，不把 HTTP 正文直接倒出来？
6. 危险动作是否二次确认，说明"移到回滚仓，不永久删除"？
7. 是否有嵌套弹窗/无法 Esc 关闭/焦点丢失？
8. 键盘能否完成主流程（Tab/Enter/Esc/方向键）？
9. 颜色之外是否有文字/图标表达状态？
10. 100%/125% 缩放下是否错位/截断？

### 4.2 文案

- 去掉"后续阶段提供""P4/P5"等开发占位。
- 三语完整；英文/日文至少主流程截图核对（历史上从未截图核对过）。
- 术语面向玩家：不出现 schema/IPC/pHash/DPAPI/GUID/asar/变异/单元测试/代号（发布说明红线；
  产品内也尽量说人话）。
- 包名/包描述是外部数据，清洗控制字符后原样显示。

### 4.3 组件边界

- VPM UI 继续懒加载；核心页面不因 VPM 停用而改变。
- 不把 VPM 状态塞进核心 Zustand store 的持久化字段；用 VPM 自己的 query/状态。
- 错误边界：VPM UI 崩溃不白屏整个应用。

## 5. 日志与诊断

### 5.1 操作记录

- 工程详情 → 操作记录：
  - 时间、类型、结果、耗时、错误码、可撤销标记；
  - 详情：变更摘要、下载大小、回滚仓路径（用户可打开）；
  - 分页/最近 50 条；不要一次拉全库。
- 失败操作给"复制错误码/打开日志"。

### 5.2 日志

- 统一 `opId`；日志文件沿用 `P.logs()`。
- 脱敏：
  - 不记录请求头/token/完整私有 URL（query 敏感键打码）；
  - 不记录包文件内容/用户路径以外的隐私；
  - 错误详情不把服务端 HTML 原文写进去。
- 设置 → 高级：打开日志目录、复制诊断信息。

### 5.3 导出诊断

- 生成一个 JSON/ZIP（用户选位置）：
  - 应用版本、Electron/Node 版本、平台；
  - VPM 设置（dataRoot 只显示盘符/末级目录？路径可保留，token 绝不）；
  - vpm.db schema、仓库数量/名称/host、上次错误码；
  - 最近 20 次操作摘要；
  - 缓存/回滚仓/备份用量；
  - 最近日志（脱敏）。
- 不含：请求头、token、包内容、工程文件、用户素材清单。
- 导出前展示"将包含什么"；主按钮"导出"。

## 6. 用量与清理

### 6.1 缓存

- 显示：缓存大小/配额、条目数、可清理量。
- 清理：LRU 未使用缓存；确认；不碰回滚仓/备份/工程；
  有下载/事务在跑时拒绝或跳过在用的 hash。
- 清理后列表仍可用（需要时重新下载）。

### 6.2 回滚仓

- 显示：按工程/操作分组、大小、时间、文件数。
- 清理：用户选择条目 → 二次确认 → `shell.trashItem`（回收站）；
  **不提供"清空全部"一键**；不自动清理。
- 打开回滚仓路径；说明"这是被替换/移除文件的副本，不是完整备份"。

### 6.3 工程备份

- 显示大小/时间；不自动删；删除记录不删文件；打开文件夹。
- 空间不足时提示用户自己清理，不擅自删旧备份。

## 7. 设置补齐

在设置 → 项目与包：

- 预发布包开关（全局）；已装包不受影响。
- 隐藏包：显示/管理隐藏列表（取消隐藏）。
- 默认 Unity 启动参数（每工程可覆盖）；校验换行/空字节。
- 更新检查开关（默认关）+ 手动"检查更新"。
- 数据根：
  - 显示路径/用量/合法性；
  - 变更数据根（可选）：
    - 目标必须非 C/合法/空或仅含 VPM 目录；
    - 复制 cache/vault/backups/templates 到新根 → 校验 → 切换设置；
    - 旧根不自动删，提示用户确认后自行处理；
    - 切换时停止所有任务。
- 危险区：
  - 停用 VPM；
  - 彻底移除（按 `VPM-ROLLBACK.md`，需多次确认）；
  - 不在这里提供"删除工程/删除素材"。

## 8. 更新检查（可选、受控）

新建 `src/main/vpm/updater.ts`（或 `src/main/updates.ts`，若不属于 VPM）。

- 设置 `checkUpdates` 默认 false；手动按钮始终可用（更新检查是独立网络，仍受 VPM 联网开关约束；
  首次点击时说明访问 GitHub）。
- 请求：`https://api.github.com/repos/W4nN1ng/Atrium/releases/latest`
  - 无 token；`User-Agent`；超时 15s；响应 ≤2 MiB；
  - 结果缓存 1 小时；失败给 code，不弹 HTML。
- 比较版本（semver）；只有更高才提示。
- 显示：版本、发布日期、发布说明摘要、资产名/大小。
- 下载：
  - 选 `Atrium-Setup-<ver>.exe`；下载到临时目录（`P.root()/updates` 或用户选择）；
  - 边下边算 SHA-256；从发布正文解析 SHA-256（支持 `：`/`—`/`–`/`:` 分隔；
    这是 `verify-release-page` 曾经假绿的坑）；
  - 不匹配 → 删除临时文件（应用自己的）/重试；不运行。
  - 正文找不到对应 hash → 不自动运行安装器；给"打开 Release 页面/手动下载"。
- 安装：
  - 用户点"下载并安装"；
  - 先确认没有 VPM 操作在跑；
  - 运行安装程序（默认可见 UI；如用 `/S` 必须明确告知并二次确认）；
  - 退出 Atrium 后由安装器接管；重启后核对版本。
- 不静默下载/安装；不在启动时自动安装；不跳过 hash。
- 如果 GitHub 不可达：给"打开 Release 页面"链接（外链确认）。

## 10. 性能与可访问性

- 目录 5,000 个包版本：搜索/筛选 <200ms；列表不卡（分页/虚拟化）。
- 解析器 200 包 <200ms（引用 P3 基线）。
- 工程扫描 10k 文件：不阻塞 UI（异步/分页）。
- 备份/下载进度节流；窗口可继续操作。
- 内存：不把 zip/大 JSON 全读进内存（P1/P4 已要求；P8 复测）。
- 键盘：
  - Tab 顺序合理；抽屉/模态焦点陷阱；Esc 关闭；Enter 主操作；
  - 排序可用键盘；列表可用方向键/Enter。
- ARIA：按钮/开关/进度有可读标签；错误用 live region（如现有组件支持）。
- 无 DOM 测试基础设施时，用 reducer/wiring 测试 + 截图/CDP 手工验收；不要假装有 DOM 回归。
