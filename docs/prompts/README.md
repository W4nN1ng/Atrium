## 1. 为什么改成任务卡

- 一份 P1/P4 提示词有 400–500 行，加上实现解剖和验收，执行 Agent 的上下文会被吃掉大半。
- 阶段太大，PR 难评审、失败难回退、问题难定位。
- 做成完整版后要方便别人维护，就必须把"业务逻辑/模块边界/测试/文档"拆成可独立完成的小块。

所以现在：

- 一个任务 = 一个分支 = 一个 PR；
- 目标 ≤ 15 个文件、≤ 500 行非测试代码；
- 每张卡自带目标、非目标、必读、文件所有权、步骤、契约、测试、完成定义；
- 架构规则、沙盒、净室、质量闸门集中在 [`_COMMON.md`](_COMMON.md) 和架构合同里。

## 2. 推荐阅读/执行顺序

### 2.1 执行一张卡

1. 读 [`_COMMON.md`](_COMMON.md)（一次就够，之后可跳过）。
2. 读 [`../VPM-ARCHITECTURE.md`](../VPM-ARCHITECTURE.md) 的 §3–§6、§10、§12。
3. 打开任务板，确认任务状态和前置；改了卡片/任务板后跑
   `node tools/check-vpm-taskpack.cjs`。
4. 只读任务卡列出的阶段规格章节 + 相关模块 README/代码。
5. 用自己的话复述"这次改哪、公开 API 是什么、失败怎么回滚、哪条测试证明"，再动手。
6. PR 里写交接段；合并后更新任务板。

### 2.2 不要做的事

- 不要一次读 P1–P9 全部提示词；
- 不要跨任务顺手重构；
- 不要在任务卡之外加功能；
- 不要把"阶段门禁"当成"任务完成"——阶段门禁是整组任务的出口条件。

## 4. 任务卡的结构

每张卡都包含：

1. **目标**：这次只做什么；
2. **不做什么**：防止顺手加功能；
3. **必读**：只列需要的阶段规格章节和代码；
4. **文件所有权**：可改/不可改；
5. **交付物**：代码、迁移、DTO、UI、文档；
6. **施工步骤**：建议顺序；
7. **契约与不变量**：模块边界、数据写入、状态机；
8. **测试与证据**：能变红的测试、真机/截图；
9. **完成定义**：含任务板状态和交接段。

共同的质量闸门、沙盒规则、停止规则在 [`_COMMON.md`](_COMMON.md)；
架构边界在 [`../VPM-ARCHITECTURE.md`](../VPM-ARCHITECTURE.md)。

## 7. 怎么把一张卡发给执行 Agent

```text
你是 Atrium 的 VPM 执行 Agent。只做任务 P4-C，不要做别的。

先读：
1. AGENTS.md
2. docs/prompts/_COMMON.md
3. docs/VPM-ARCHITECTURE.md 的 §3–§6、§10、§12
4. docs/prompts/tasks/P4-C.md（本任务卡）
5. 任务卡“必读”列出的章节/代码

动手前用 5–10 行复述：改哪些文件、公开 API、失败怎么回滚、哪条测试证明。
完成后按任务卡的“交接”格式写 PR；不要读其他阶段提示词。
```

不要附加上一阶段的聊天记录；交接信息在 PR 的交接段和任务板里。

## 8. 每个任务都要遵守的共同约束

- 从最新 `main` 开 `codex/vpm-<task>-*`；不直推 `main`。
- 核心 `library.db` schema 不动（`SCHEMA_VERSION=11`）；VPM 用自己的 `vpm.db`。
- 缓存/回滚仓/备份必须在非 C 数据根；没有就不启用。
- 永不永久删除用户文件；移除的文件先进回滚仓。
- 绝不手写 `.meta`；只搬运包内已有 `.meta`，或让 Unity 生成。
- 不写 VCC；`com.avca.bridge` 是受保护包。
- 主进程不返回 UI 句子；错误码 + 三语文案。
- 不复制 ALCOM 代码/文案/图标/模板/测试；写代码时关掉 ALCOM 源码。
- 测试用沙盒 `AVCA_APP_HOME` + `AVCA_REQUIRE_SANDBOX_HOME=1`；
  不碰 `E:\vrc\A`、`E:\Atriumdate`、`%APPDATA%\A\library.db`。
- 真实测试数字/退出码；未验证就写未验证。
- 合并后构建并更新本机安装版（VPM 默认关闭）；P9-E 才发 Release。

## 9. 交接包

每个任务/阶段合并后，在 PR 里留：

```text
Task: P?-?
状态: 完成 / 部分 / 阻塞
公开 API/契约变化: ...
新增/修改模块 README: ...
已验证: ...
未验证: ...
给下一个任务: ...
```

阶段收口时再补一段：

```text
阶段：P?
合并 commit：
本机安装版本：
新增文件/表/接口：
已知差异/未验证：
回退验证：
```

下一张卡先读交接段，不重读整个实现。

## 10. 如果中途要停

- 停用 VPM 即可回到核心原样（`docs/VPM-ROLLBACK.md` L1/L2）。
- 已合并的任务不需要回退；未完成的分支保留，不强推 `main`。
- 未发布的 VPM 功能默认关闭，用户不会被迫使用。
- 彻底放弃：按 L3/L4/L5 做，保留备份和证据。
