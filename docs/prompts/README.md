## 每份提示词的结构

一份能直接交给执行 Agent 的提示词，必须同时回答四个问题：

1. **要做成什么**：用户可见行为、明确不做、完成定义。
2. **ALCOM 是怎么实现的**：`§X.5` 里的行为/架构观察（仓库持有器、包集合、
   解析队列、事务顺序、Hub 发现、模板/unitypackage、备份收集器、迁移、VCC 互操作、命令/更新）。
3. **我们怎么独立实现**：自己的数据形状、模块位置、状态机、失败点、施工顺序。
   **不是把 ALCOM 代码贴进来，而是把"输入 → 处理 → 输出 → 失败后怎么办"讲清楚。**
4. **怎么证明做对了**：自动化测试、失败注入、真 Unity 沙盒、回退验收、对账表证据。

如果某个阶段的提示词只有功能名和验收标准、没有第 2/3 层，就不要开工；
先回 guide 补对应章节，再让 Agent 动手。

## 怎么发给执行 Agent

1. 先发 **P0** 的完整内容；不要附加上一阶段的聊天记录。
2. 要求它先读提示词里列的文档（尤其 guide 的对应章节），
   用自己的话复述"ALCOM 机制 / 我们的实现 / 施工顺序"后再写代码。
3. 它必须在 PR 里给：
   - 实际测试数字/退出码；
   - 手工验收截图；
   - 回退验收；
   - 未验证项；
   - 净室检查表。
4. P0 PR 合并、本机安装版验证后，再发 P1。
5. 任何阶段发现"必须改核心 schema / 核心联网 / 永久删除" → 停止，回到规划。
6. P4 是 go/no-go：事务失败注入不能全回滚，就不要进 P5。
7. P9 发布前，先做回退演练；没有演练证据不发版。

## 每个阶段都要带的"共同约束"

这些已经写进每份提示词，但发的时候可以再强调：

- 从最新 `main` 开 `codex/vpm-pN-*` 分支；不直推 `main`。
- 不碰未提交的 0.8.0 手势改动；不 reset/stash 覆盖。
- 核心 `library.db` schema 不动（`SCHEMA_VERSION=11`）；VPM 用自己的 `vpm.db`。
- 核心不联网；VPM 网络默认关闭、首次明确同意、无遥测。
- 缓存/回滚仓/工程备份必须在非 C 数据根；没有就不启用。
- 永不永久删除用户文件；VPM 移除的文件先进回滚仓。
- 绝不手写 `.meta`；只搬运包内已有 `.meta`，或让 Unity 生成。
- 桥接只装 `Packages/com.avca.bridge`；VPM 把 `com.avca.bridge` 列为受保护包。
- 主进程不返回中文；只给 code/key + 参数。
- 不复制 ALCOM 代码/文案/图标/模板/测试；写代码时关掉 ALCOM 源码。
- 测试用沙盒 `AVCA_APP_HOME` + `AVCA_REQUIRE_SANDBOX_HOME=1`；不碰 `E:\vrc\A`、
  `E:\Atriumdate`、`%APPDATA%\A\library.db`。
- 真实测试数字/退出码；未验证就说未验证。
- 合并后构建并更新本机安装版（VPM 默认关闭）；P9 才发 Release。

## 阶段间的"交接包"

每个阶段合并后，在 PR/Issue 里留一个短交接：

```text
阶段：P?
合并 commit：
本机安装版本：
新增文件/表/接口：
已知差异/未验证：
下一阶段需要知道的坑：
回退验证：
```

下一阶段的执行 Agent 先读这个交接，再读自己的提示词。

## 如果中途要停

- 停用 VPM 即可回到核心原样（`docs/VPM-ROLLBACK.md` L1/L2）。
- 已经合并的阶段不需要回退；把未完成的分支保留，不要强推 `main`。
- 未发布的 VPM 功能默认关闭，用户不会被迫使用。
- 如果要彻底放弃：按 L3/L4/L5 做，保留备份和证据。
