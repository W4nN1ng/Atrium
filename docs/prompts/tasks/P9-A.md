# P9-A 安全硬化

> 阶段规格：`../VPM-P9.md`（只读 §2.1）
> 任务板：`../../VPM-TASKS.md` · 共同规则：`../_COMMON.md` · 架构合同：`../../VPM-ARCHITECTURE.md`
> 前置：P8-E
> 覆盖对账项：I4 / I5 / I6 / I7
> 建议上下文：≤ 25k tokens

## 目标

- 复核路径/zip/网络/密钥/深链/模板的安全边界，补静态检查与攻击用例。
- 确保没有永久删用户文件、没有写 C 缓存、没有绕过同意联网、没有明文密钥。
- 修复发现的问题，不扩大功能。

## 不做什么

- 不加新功能/新协议。
- 不降低现有校验换兼容。
- 不忽略“低概率”攻击面。

## 必读（只读这些）

- `docs/VPM-ARCHITECTURE.md` §5、§10.3
- `docs/prompts/VPM-P9.md` §2.1
- `docs/VPM-CLEANROOM.md` §7

## 文件所有权

- 修改：安全相关实现/测试
- 新增：`tests/vpm/security/*.spec.ts`
- 修改：静态架构闸门

## 交付物

- 攻击矩阵：zip-slip/symlink/ADS/保留名/长路径/深链/token。
- 静态检查：无永久删、无 C 缓存、无未同意网络。
- 修复与回归。
- 安全结论。

## 施工步骤

1. 列攻击面与现有防线。
2. 补攻击用例（先红）。
3. 修实现/闸门。
4. 跑全量/typecheck/build。
5. 写安全报告。

## 契约与不变量

- 任何修复不降低校验。
- 错误码不泄露敏感信息。
- 安全测试可重复。

## 测试与证据

- 攻击矩阵全绿。
- 静态检查通过。
- 全量测试/typecheck/build。

## 完成定义

- 安全门禁通过。
- 未验证项明确。
- 更新 `docs/VPM-TASKS.md`：该任务标为 done（或按实际状态标 blocked/review）。
- PR 含交接段；未验证项明确写出。
