# P8-A UI 收口、按钮纪律与组件边界

> 阶段规格：`../VPM-P8.md`（只读 §4）
> 任务板：`../../VPM-TASKS.md` · 共同规则：`../_COMMON.md` · 架构合同：`../../VPM-ARCHITECTURE.md`
> 前置：P4-E、P5-D、P6-D、P7-E
> 覆盖对账项：I1 / I2 / A20 / B24
> 建议上下文：≤ 30k tokens

## 目标

- 逐屏检查项目页/设置页，按“一个主操作”收口；批量操作选中后才出现。
- 拆分过大的容器组件，展示组件不直接调 IPC；统一空/错/loading/危险确认。
- 补包图标失败回退、搜索/排序等轻量项，不新增重型 UI。

## 不做什么

- 不新增功能/后端能力。
- 不新增顶级导航。
- 不为了“好看”大改现有视觉风格。

## 必读（只读这些）

- `docs/VPM-ARCHITECTURE.md` §11
- `docs/prompts/VPM-P8.md` §4
- `renderer/vpm/`、现有项目页/设置页

## 文件所有权

- 修改：`renderer/vpm/` 组件/hooks/i18n
- 新增：`tests/renderer/vpm-ui.spec.ts`
- 截图：`docs/screenshots/vpm-p8-*`

## 交付物

- 逐屏检查表：入口/主按钮/批量/危险操作/空错状态。
- 组件边界：api→hooks→components；无直接 IPC。
- 包图标失败回退/搜索排序等轻量项。
- 截图对比与已知限制。

## 施工步骤

1. 先列逐屏清单与问题。
2. 按清单改组件/按钮。
3. 补空/错/危险确认/键盘。
4. 截图对比。
5. 写“按钮纪律”结论。

## 契约与不变量

- 不改变已有功能的语义。
- 不引入新依赖/新导航。
- 危险操作仍有二次确认。

## 测试与证据

- 渲染 wiring/组件边界。
- 关键截图。
- 全量测试/typecheck。

## 完成定义

- 按钮纪律通过；没有直接 IPC 的展示组件。
- 截图证据在 PR。
- 更新 `docs/VPM-TASKS.md`：该任务标为 done（或按实际状态标 blocked/review）。
- PR 含交接段；未验证项明确写出。
