# P8-E 性能、可访问性与全量回归

> 阶段规格：`../VPM-P8.md`（只读 §10、§11）
> 任务板：`../../VPM-TASKS.md` · 共同规则：`../_COMMON.md` · 架构合同：`../../VPM-ARCHITECTURE.md`

> 覆盖对账项：I1 / I2 / I10 / A13
> 建议上下文：≤ 25k tokens

## 目标

- 给目录/解析/备份/事务加基准，确认不卡 UI、内存可控。
- 键盘/焦点/Esc/Enter/对比度/非颜色状态检查；补必要修复。
- 全量回归 + 真机关键路径；把结果写进报告。
- 可选补 A13：Unity 已在运行时把窗口顶到前台；失败不影响启动/管理，不做也不阻塞门禁。

## 不做什么

- 不做新功能。
- 不为性能改事务语义。
- 不忽略低配机/长路径。

## 必读（只读这些）

- `docs/VPM-ARCHITECTURE.md` §2、§10
- `docs/prompts/VPM-P8.md` §10、§11
- `tests/perf/` 现有基准

## 文件所有权

- 新增/修改：`tests/perf/vpm-*.spec.ts`
- 修改：必要的 UI 可访问性
- 新增：`docs/VPM-PERF.md` 或报告段

## 交付物

- 基准：目录查询/解析/备份/事务；记录 p50/p95/内存。
- 可访问性检查与修复。
- 全量回归/真机关键路径记录。
- 性能结论/瓶颈。

## 施工步骤

1. 先量基线，不先优化。
2. 找 p95/内存异常。
3. 做最小修复。
4. 跑可访问性检查。
5. 全量回归并写报告。

## 契约与不变量

- 优化不改变业务语义。
- 不隐藏回归。
- 基准可重复。

## 测试与证据

- 基准在预算内/有对比。
- 键盘/焦点检查。
- 全量测试/typecheck/build。

## 完成定义

- 有可重复的性能证据。
- P8 全部门禁通过。
- 更新 `docs/VPM-TASKS.md`：该任务标为 done（或按实际状态标 blocked/review）。
- PR 含交接段；未验证项明确写出。
