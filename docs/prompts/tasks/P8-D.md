# P8-D 逐行功能对账与缺口分诊

> 阶段规格：`../VPM-P8.md`（只读 §9）
> 任务板：`../../VPM-TASKS.md` · 共同规则：`../_COMMON.md` · 架构合同：`../../VPM-ARCHITECTURE.md`
> 前置：P8-A、P8-B、P8-C
> 覆盖对账项：全部
> 建议上下文：≤ 30k tokens

## 目标

- 按 `VPM-PARITY.md` 逐行填实际状态/证据/差异/去向。
- 把缺口分成：必须修/接受差异/后续任务；不把“完整”悄悄降级。
- 输出可签字的对账结论与 P9 只修清单。

## 不做什么

- 不新增功能。
- 不把未验证写成完整。
- 不删对账行。

## 必读（只读这些）

- `docs/VPM-PARITY.md`
- `docs/VPM-ARCHITECTURE.md` §2、§14
- 各任务卡/PR/测试报告

## 文件所有权

- 修改：`docs/VPM-PARITY.md`（证据列）
- 新增：`docs/VPM-GAPS.md` 或对账结论段
- 修改：`docs/VPM-TASKS.md` 新增缺口任务

## 交付物

- 每行：实际状态/证据/差异/去向。
- 缺口清单：必修/接受/后续。
- P9 只修清单。
- 已接受差异写进 README/DEVELOPMENT。

## 施工步骤

1. 按 A–K 分组逐行核对代码/测试/截图；K（素材/桥接联动）不能跳过。
2. 缺证据的补证据或标未验证。
3. 把缺口写成任务卡。
4. 输出结论与签字。
5. 更新任务板。

## 契约与不变量

- 没有空白行。
- 完整项必须有证据。
- 降级必须写原因。

## 测试与证据

- 对账表无空白/无待定。
- 每个完整项有测试/真机/截图。
- 缺口都有去向。

## 完成定义

- P8 门禁：对账可签字。
- P9 范围明确。
- 更新 `docs/VPM-TASKS.md`：该任务标为 done（或按实际状态标 blocked/review）。
- PR 含交接段；未验证项明确写出。

## 交接（写进 PR）

```text
Task: <ID>
状态: 完成 / 部分 / 阻塞
公开 API/契约变化: ...
新增/修改模块 README: ...
已验证: ...
未验证: ...
给下一个任务: ...
```

共同质量闸门、沙盒规则、停止规则见 `../_COMMON.md`。
