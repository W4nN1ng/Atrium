## 2. 修法（A–F）

### A. 容器视图能滚（P0）

1. `BundleDetail.tsx:254` 补 `min-h-0`。

3. 判据（活体，打包版真窗口）：进一个 ≥20 行的容器 → 列表元素 `scrollHeight > clientHeight`；`scrollTop = 300` 读回 ≥300；派发一次真实 `WheelEvent` 后 `scrollTop` 必须变。**三条先红一遍再改绿**（老规矩：写完用例要回退确认它会红）。

### B. 旧占位拆干净（P0，报障 1）

- 行内那颗「导入」+ 行双击 + Enter：**全部走 store 里那条真路** `importAsset(那一行的 id)`；多个包时它自己会打开成员选择面板（判据在 `shared/memberPick.ts:cardImportChoice`，不替他挑）。

### C. 「筐」不该变成一张卡（P1，报障 3 的第 ① 件）

新判据（推荐）：**目录名本身就是"筐"（纯计数 / 纯归类词：`道具22件`、`ERP用12件`、`插件17件`、`更新`、`重要！`）时，它不该成为一张卡，要往下摊平，里面的每个产品各自成卡。**

- 直接拖 `道具22件` → **22 张顶层卡**（每件自己还能有版本/变体归并：`StoZeroCustomEX.zip` + `_v1.01` + `_v1.10` 仍是一张卡的三个版本，这条不动）。
- 拖 `插件道具合集-初音的VRC小店` → 外层那张 Bundle 卡**保留**（名字写着"合集"、一个卖家打包卖的），里面 `道具22件` 这一项按 **Q2** 决定是"1 项"还是"摊平成 22 项"。
- 保住 R2b 真正要治的病：`4952737/INVICTA` 这种 ID 目录穿透照旧；"一件商品的几个分包/几个版本"不许撕碎。
- 判据：夹具直接用他这两个真目录的形状（`道具22件/4533350巧克力/{4533350巧克力.zip, 一张封面 png}`）；**反向夹具必须留**（`ABT 左手用/右手用`、`Grimoir` 11 变体不许被摊碎）。

### D. 显示名：磁盘名够格时不许被顶掉（P1，报障 3 的第 ② 件）

**不是一刀切"永远用磁盘名"** —— `6447797.rar` 这种纯 Booth id，用主体名 `Noir Luxe Airi` 明显比磁盘名好，那正是 §A3 当初的动机。所以规则是：

1. 用户手改过的名字（最大，不动）；
2. **磁盘名不垃圾时 → 用磁盘名**（清洗掉版本/扩展名之后）；垃圾判据**复用现成的** `reanalyze.nameIsGarbage`（UUID / 长 hex / 纯 id / 还挂着扩展名 / `.0版本` 残骸），不另造一套；
3. 磁盘名垃圾时 → 用主体名（现状）；
4. 被降级的那个名字**不许丢**：进搜索别名 + 卡片副标题（例如「包内名：Holy Spice Kaguya」）。

- 为什么这样切：他按**磁盘上那个名字**找东西。`修女` 变成 `Holy Spice Kaguya`，下次他在资源管理器里看见 `修女`、在 A 里搜 `修女` 都对不上那张卡。
- 判据：改名前后各搜一次（`修女` 和 `Holy Spice Kaguya` 都要能搜到同一张卡）；`nameIsGarbage` 那条判据要有"磁盘名是 id → 仍用主体名"的反向用例，防止修过头。
- 分类（第 ③ 件）：C 做完，容器那一行的分类就消失了，22 件各自判。**但本轮只量不改**（Q10）。

### E. 拖文件夹"没反应"（P1，报障 4）

根因还没定死，所以分两段：

- **不依赖复现就能做的三件**（方向都是"永远不要静默"）：
  1. `onDragOver` 里也 `setActive(true)` —— 指针只要还在窗口里，`dragover` 会持续触发，高亮不可能"灭着"。
  2. 去掉 `depth` 计数器，改成「最后一次 `dragover` 时间戳 + 400ms 内没有新事件才熄灭」，`dragleave` 只在真的离开窗口时算。
  3. `drop` 拿到 0 个本地路径时**必须说一句**（"没拿到这个文件夹的路径 —— 试试资源管理器右键『发送到 Atrium』"）并写日志。
- **要复现才能定死的那件**：加 dev-only 计数日志（`dragenter/dragleave/dragover/drop` 各几次 + 文件数），下次他撞上就一眼能看出是"事件没进来"还是"我们没接住"。
- 判据：CDP 派发合成 DragEvent 序列（enter → over×3 → leave → drop 且 0 files），断言高亮出现过、drop 后有提示、日志有计数。⚠ **真实 OS 拖拽那条我只能标"未验证"** —— 命令行发起不了一次资源管理器拖拽，这条要他配合复现。

### F. 旧文案大扫除（P0，报障 5）

一条**规矩**代替逐条打补丁：**界面文案里不许出现里程碑编号、内部代号、"以后某个版本会做"这类会过期的话**。界面只说两种话：现在能做什么、现在不能做什么以及为什么。

1. `在 M5 交付` / `M5-A 剩余部分交付` / `将在 M5 交付` / `M5-B 交付` —— 报障 1 那几处 + `project.m1Note` + `undo.ts:341` 那句抛错（见 **Q6**）。
2. 内部代号 **「A」**（#102）。
3. **死文案**：`library.importDeferred` 等没人引用的，扫出来一起删。
4. **说反话的**：`ui.ts:1499` 那种"实际做了 A、话说的是 B"。

- 判据：一条用例扫三份语言文件 + 源码里的 `t('…')`，命中 `M\d` / `交付` / `里程碑` 就红（白名单逐条写明白，比如指事实的过去时）；「A」那条正则只抓"当主语用的裸 A"，别把 `Ctrl+A`、`E:\vrc\A`、`M5-A` 抓进来（我这次扫的时候先误抓了这些）。
