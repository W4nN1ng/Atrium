# 未导入素材的封面预览

用户已验收原工程候选封面，并授权进入下一阶段。目标：素材只存在于 ZIP / unitypackage 中时，也能在 Atrium 看到真实模型候选、调整方向并确认保存；无需向改模工程导入素材。沿用此前已授权的分支、完整验收、PR、自行合并流程。

## 范围与体验

封面窗口提供「从素材包预览」和「从 Unity 工程预览」两种来源。前者默认尝试发现本机 Unity 2022.3；未发现时可选择 Unity.exe。着色器依赖可复用用户选择的已登记工程中的 lilToon 资源，但仅复制渲染资源。保留原工程选择、搜索和场景姿态拍摄。旧的封面关联继续正常使用。

首版输入为原始 unitypackage、ZIP 内的 unitypackage 及目录中的 unitypackage。合集成员继续遵守已验证的 GUID / 包成员归属；歧义拒绝猜测。各阶段显示读取、启动、加载、生成进度，可取消。先显示 8 个候选，最多 50 个；不自动选中或保存。只在用户确认保存时改变卡片。

## 隔离与数据

应用数据目录下的 `cover-previews` 保存明确带所有权标记的独立工程；绝不登记为用户工程、触发集合自动切换或写入导入日志。仅在这些目录内创建、加载和清理资源；源 ZIP、素材库和用户工程只读。用户工程桥接不因包预览而更新。

unitypackage 的 `pathname`、`asset`、`asset.meta` 经 GUID、相对 Assets 路径、文件类型、冲突、限额校验后落到独立工程。保留资源 GUID 和有效导入 metadata。允许模型、预制体、材质、图片、网格/纹理 asset、Shader/HLSL/CG 资源；排除 C#、程序集、原生插件、程序集定义和可执行文件。不运行供应方的脚本、Animator、MA/NDMF 或 SDK 构建。

输入和解压上限分别为 512 MiB 和 2 GiB，最多 32 个包、20,000 个扫描条目、10,000 个 GUID、4 KiB 路径、目录深度 8；沿用现有清单限制。读取具有取消信号和 45 秒截止时间。重复 GUID 或路径内容冲突拒绝覆盖。符号链接、越界和不明所有权目录禁止写入或清理。

Shader 依赖首版支持原包自带资源和本机已登记工程中的 `Packages/jp.lilxyzw.liltoon` 渲染资源；保留 package 路径及 GUID，排除脚本，不联网安装。缺失其他依赖明确提示，保留手动选择与本地图片路径。Unity 仍使用本机许可证及 GPU；不承诺没有 Unity 安装时渲染。

## 进程与接口

复用现有静态渲染器、640×480 PNG 校验及最长边 320 像素缓存。一个预览服务同一时间持有至多一个独立 Unity 进程，排队请求可取消；切换包先关闭旧进程。启动截止 120 秒，闲置关闭，应用退出关闭。只关闭自己持有的进程，不按进程名结束用户 Unity。

`PackagePreviewWorker` 创建最小 Built-in 工程、可信桥接和 Worker 启停脚本；通过现有文件信箱执行候选查询和渲染。编辑器定位优先已有 `unityExePath` 设置，其次 Unity Hub 本机安装记录；无法定位时由用户选择。内部 Worker 使用明确参数 / 所有权标记，工程发现过滤它。

`PackageCoverProvider` 将只读清单、资源准备、Worker 及候选 GUID 映射组合起来。界面使用现有 cover request ID 和 discard 机制，新增原包发现及进度接口。原包目标保存为稳定的包 GUID 标识，不把临时 GlobalObjectId 或临时工程路径当作持久关联。

数据库迁移为 `asset_cover.source` 新增 `package`，完整保留已有图片、原图、工程和对象记录。原包封面重启后保留，更新时重新从当前原文件定位同一 GUID。批量更新支持该来源，手动图片保护不变。源文件丢失、依赖缺失、资源改变和取消均不得替换旧封面。

原包请求的 `projectId` 为空，另用 `dependencyProjectId` 指定可选依赖。保存的 `source=package` 记录以 `project_id` 保存该依赖工程 ID，绝不保存临时预览工程 ID。原包与依赖或依赖内部的重复 GUID 一律拒绝，包括字节完全相同的副本；原包内相同资源的归并仍按路径和内容一致性判断。

首次心跳前写入自有子进程租约，清理同时检查租约和心跳中的 PID。仅删除严格匹配所有权、路径及无链接条件的非活动工程，退出清理未完成时由后续会话重试。包内 tar 条目按序流式处理，避免小文件并行累积监听和竞争目录创建；二进制或不支持类型的 `.asset` 略过并显示部分资源提示。

## 验收

单元测试覆盖脚本剔除、路径 / GUID / 内容冲突、合集归属、限额与取消、进程所有权和关闭、源文件变化、迁移保留、候选关联及原图保护。实际独立 Unity 工程从百奇 / 巧克力原 ZIP 提取资源后生成图片，起始工程没有这些物品。实际 Electron / IPC / SQLite 验证进度、候选、方向、明确保存、取消、恢复、批量及重启。

全部代码只在 `codex/package-cover-preview` 分支开发。完整测试、类型检查、构建、worker 依赖和真实操作通过后才能创建 PR；确认远端状态与验证提交一致后自行合并。第三方资源、Unity 安装及生成图片不随仓库提交。
