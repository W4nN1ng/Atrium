# Atrium 0.2.0

给 VRChat 改模玩家用的素材管家，Windows 桌面程序。

**一句话**：把一坨散着的 `zip / rar / 7z / unitypackage` 丢进去，它替你解压、读懂内容、分类归档；
你打开哪个 Unity 工程，它就自动切到那个模型该在的分区，勾选后一键批量导入。

按 24 GB、几千个文件的真实库设计，不是给十几个文件用的小工具。

## 能做什么

**收进来**

- 四条入口：拖进窗口 / 资源管理器右键「发送到 Atrium」/ 命令行 `Atrium.exe --ingest <路径>` / 监视文件夹
- 格式：zip（含 cp932 / Shift-JIS 日文文件名不乱码）、rar / RAR5、7z（**含头部加密 `-mhe`**）、`.unitypackage`
- 要密码的包会问你要；勾「记住这个密码」之后，下次撞见同一个包它自己就试，不用再输
- 一个压缩包里有多个商品时，可以只勾其中几个成员导入，不用整包解

**看得懂**

- 分类不是只看文件名：会读包里的内容（模型 / 材质 / 贴图 / 音频 / 脚本…）、Booth ID、
  内层 `.unitypackage`、体积与条目结构，然后给出**置信度和理由**
- 没把握的进「待复核」而不是硬塞进库；你手动改过的分类会被记下来，下次同类不再问
- 三级结构：合集 → 子项 → 版本。一个 rar 里 17 件是一个筐（一张卡「含 17 项」），
  不会被撕成 17 张；同一件商品的多个体型 / 版本会并成一张卡，并分列显示「适配模型 ×2 · 版本 ×2」
- 搜索支持拼音、假名、罗马字互搜（`shinano` / `シナノ` 能找到同一件），分类的口语叫法也能搜
  （`yifu` → 服装），在设置里加词不用重启就生效

**管得住**

- 缩略图自动生成、卡片封面、聚合 / 平铺双视图、集合（分区）管理
- **改分类会把文件真的搬到新目录**：搬之前给你看清单（几个文件 / 目标在哪 / 会覆盖谁），能整批撤销
- 库健康检查：重复项、封面近似（pHash）、游离文件、僵尸记录、超大文件；能重建索引、备份数据库
- 删除一律走**回收站**，永不永久删除；大部分操作 `Ctrl+Z` 能撤回
- 已经有一个库？首启向导第①步指过去，它数一下会问「**接管这个库**（只登记，一个文件都不搬不改名）
  / 当成空库」，选接管还会顺手关掉"高置信度自动归档"，每张卡都等你确认才动盘

**跟 Unity 配合**

- 桥接是一小段编辑器脚本，**只写进工程的 `Packages/com.avca.bridge/`，不动 `Assets/`、不改场景**；
  首次发现某个工程会问一句，也可以一屏批量装（默认全勾，逐个可取消）
- 打开某个工程 → 自动切到对应模型的集合分区（同一工程 5 分钟内只自动切一次，拿不准就不切只更新顶栏）
- 批量导入串行执行、逐条报进度；导入前扫冲突并列出将被覆盖的文件，被覆盖的先备份；
  Unity 正在 Play 模式时命令排队而不是报错，退出 Play 自己接着跑完
- 撤销导入会把资源真的删回去，并告诉你新建了几个 / 覆盖了几个 / 有没有删不掉的
- 详情页能反查「这张卡在哪些工程装过、哪几次被退回」
- 常驻托盘；`Ctrl+Alt+A` 在鼠标位置弹出小投递窗直接丢文件；从托盘唤回主窗口时**只置顶约 1.2 秒、
  不抢你的键盘焦点**（凭一条"检测到 Unity"就抢走焦点算骚扰，这条是故意的）
- 界面三语：简体中文 / English / 日本語

**完全离线**：不联网、不上传任何东西（连"AI 分类兜底"这个功能都还没做，见下面限制）。

## 第一次怎么用

1. 装好打开 → 走四步向导：① 素材库存哪儿 → ② 素材从哪儿来 → ③ 给 Unity 工程装桥接 → ④ 收尾。
   **只有第 ① 步不能跳**；中途点「稍后配置」不会拦你，但侧栏会一直留着「库还没配好，点这里继续设置」
2. 已有库就选**接管**；新库就指个空目录
3. 把东西丢进去（或右键「发送到 Atrium」）。等它跑完分析，在「待确认 / 待复核」里过一眼，
   点「全部入库」
4. 装过桥接的工程打开 Unity → 顶栏会出现「正在编辑 xxx」的横幅，点它就切到对应分区

## 这版还没有 / 已知限制

- **未签名**，第一次运行要手动放行
- **运行目录（数据库 / 缩略图 / 暂存 / 日志）固定在 `%APPDATA%\A`**，不能搬到别的盘（素材库根本来就能随便放）
- **一次导完好几批时，界面只能退回最后那一批**（第一批得从维护页的账里想办法）
- 桥接还是 1.0.0，所以：工程里**现在**装了哪些 GUID 答不了（只能答"A 导过哪几次"）、
  撤销后工程里会留下这次新建的空目录和它们的 `.meta`、`topFolders` 一类指纹信息拿不到
- 依赖分析的结果没做上文展示；重复项**只列不删**（删哪份由你决定）；封面近似只比封面图，不比非图片素材
- 内置词典只读（能加自己的、能删已学的，不能改内置表）；**汉字→日语读音的检索不支持**
  （`sokubaku` 搜不到 `束縛`）—— 这是权衡后的决定，理由写在 `docs/SEARCH.md`
- LLM 兜底（拿不准时问模型）完全没做
- 只在 **Windows 11（build 26200）x64 + Unity 2022.3.22f1** 上实测过；Windows 10 没测
  （没有第二台机器），理论上只有托盘/全局热键那一块与系统版本有关

## 数据放在哪（也说明卸载会留什么）

| 内容 | 位置 |
|---|---|
| 你的素材本体 | 你指定的库根（例如 `E:\vrc\A`） |
| 数据库 / 缩略图 / 暂存 / 备份 / 日志 | `%APPDATA%\A\` |
| 设置（含库根、开关、首启进度） | `%APPDATA%\A\settings.json` |
| 记住的压缩包密码 | `library.db` 的 `password_vault` 表，**DPAPI 密文**，界面上永远不显示密码本身 |
| 你加的口语叫法 | `%APPDATA%\A\categories.user.json`（内置词典只读，升级不丢） |

卸载只删程序本体（`deleteAppDataOnUninstall: false`），上面这些都在安装目录之外。

## 质量与验证

- **1378 项用例：1369 通过 / 9 跳过**（106 个测试文件）。TypeScript 两个配置零报错。
  跳过的 9 项都是需要真库写入授权、或需要本机 Unity 编译器环境的那几类，不是被藏起来的失败
- **两张变异回扫表**：把 42 处（R4）与 29 处（M7）修复逐个改回旧写法，每一处都有用例变红 ——
  用来防"测试写着挺全，其实撤掉修复也不红"
- **打包版真机首启六条**：四场 91 条判据、0 条红（接管之后整棵树 md5 逐一不变、
  没勾的工程连 `Packages/` 都不建、真 `-mhe` 包"记住 → 重启 → 不再问"、8 个工程一次冒出来问完为止）
- 5 万条合成库性能实测（闸门写在用例里，数字每次跑都打出来）：
  分片后台建索引 50000 条 / 118.6 万条别名 / 63 片，共 18.7–24.2 秒，**第一片 423–520 ms 后就能搜**；
  增量重建 0.21–0.58 ms/条（闸门 0.6）；搜索 p95 = 21.7–37.7 ms（闸门 100 ms）；
  500 张卡翻一页：聚合 287–334 ms、平铺 201–235 ms（闸门 3 秒）

## 自己构建

```bash
git clone https://github.com/W4nN1ng/Atrium.git
cd Atrium
npm install
npm run setup              # 拉 Electron 本体 + 两个 ABI 的 better-sqlite3 预编译包
node tools/fetch-7z.cjs    # 拉 7-Zip（含 Rar 解码器；许可原因不随仓库分发）
npm test
npm run build              # 出 dist\Atrium-Setup-<版本>.exe 与便携版
```
