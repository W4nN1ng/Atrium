# VPM 合并的净室与版权规则

> 这份文件不是法律意见，是**工程纪律**。目的：Atrium 的 VPM 功能由我们自己实现，
> 只借鉴 ALCOM/vrc-get 的**行为与架构思想**，不把它们的代码、文案、资产带进来。
>
> 适用对象：所有参与 P0–P9 的人/Agent。每个阶段的 PR 都要对照本文最后一张检查表。

---

## 1. 三条底线

1. **可以研究"它怎么表现"，不可以复制"它怎么写/怎么说/怎么画"。**
2. **实现时只看我们自己的行为规格与公开协议，不照着 ALCOM 源码逐行翻译。**
3. **一旦怀疑某段实现是"翻译"出来的，停下来重写，并记录。**

---

## 2. 可以做什么

- 阅读 ALCOM/VRChat 的**公开用户文档**、更新日志、VPM/VCC 的公开文件格式说明。
- 阅读 ALCOM/vrc-get 源码，回答"这个功能在什么条件下做什么、错误怎么分类、
  文件写入顺序是什么"这类**行为问题**。
- 用黑盒方式观察 ALCOM 的界面流程、提示时机、失败后的状态（不截图描摹、不抄文案）。
- 使用公开的协议字段名（如 `vpm-manifest.json` 的 `dependencies`/`locked`、
  仓库 JSON 的 `packages`/`versions`/`zipSHA256`），因为它们是互操作所必需的接口事实。
- 使用公开的官方仓库 URL、VRChat 包 ID、Unity 版本格式。
- 使用宽松许可的第三方库（MIT/ISC/Apache-2.0/BSD），并按许可证保留声明。

## 3. 不可以做什么

### 3.1 代码与测试

- 不复制任何 ALCOM/vrc-get 的源代码、代码片段、函数名组合、类型定义、注释、
  TODO、错误文案、日志格式。
- 不复制它们的测试用例、夹具、快照、期望值表。
- 不把 Rust 代码"逐行翻译"成 TypeScript；不把它们的模块拆分原样搬过来。
- 不引入 `vrc-get` 的 crate、二进制、WASM 或 npm 包作为运行时依赖。
- 不反编译、不混淆还原、不绕过许可证。

### 3.2 界面与文案

- 不复制 ALCOM 的 UI 文案、按钮名、提示语、空状态、错误句、更新日志措辞。
- 不复制图标、插图、logo、字体、颜色主题、布局截图。
- 不使用 "ALCOM" 作为 Atrium 的功能名、产品名、安装包名、协议名。
- 可以在"兼容性说明"里**事实性提及** VCC/ALCOM（例如"可导入 VCC 的仓库设置"），
  但不使用它们的 logo，不暗示官方背书。
- 所有界面文案由我们自己写，进 Atrium 的三份 i18n 文件。

### 3.3 模板与资产

- 不复制 ALCOM 内置模板的 tar.gz、ProjectSettings、场景、材质、图标、示例资源。
- 不复制 VRChat SDK 的包内容并随安装器分发；运行时从官方仓库获取。
- 不复制 ALCOM 的模板清单、描述、分类、封面。
- 我们的"角色/世界"模板 = 我们自己的空白工程骨架 + 官方包依赖（包 ID + 版本范围），
  不含任何第三方美术资源。

### 3.4 数据与隐私

- 不把 VCC 的 `vcc.liteDb`、用户工程、仓库请求头、包缓存提交进仓库。
- 测试夹具自己造；需要真实包时从官方仓库现拉，不提交二进制。
- 不把用户真实库路径、token、私有仓库 URL 写进文档/日志/截图。

## 4. 净室工作流（推荐）

### 4.1 两个角色（可以由同一人分时扮演，但要分时）

**观察者（Observer）**

- 只回答行为问题；产出"行为规格"与"观察日志"。
- 不写产品代码。
- 观察日志只写**自己的话**，不贴源码、不贴大段注释、不贴截图。

**实现者（Implementer）**

- 只读行为规格、公开协议、Atrium 代码。
- 写代码时不打开 ALCOM 源码；需要澄清时，向观察者提问，拿回一句行为描述。
- 如果发现自己在回忆某段源码的结构，先停，改用白纸设计。

> 同一个人也可以做，但至少做到：**先关掉 ALCOM 源码，再写代码；写完后做相似度复核。**

### 4.2 观察日志格式

放在本文件第 8 节。每条包含：

| 字段 | 说明 |
|---|---|
| 日期 | 绝对日期 |
| 来源 | 公开文档 / 源码区域（只写模块名，不贴代码）/ 黑盒观察 |
| 问题 | 我们要决定的行为问题 |
| 观察 | 用我们自己的话描述行为、边界、错误 |
| 落地 | 对应阶段/文件/测试 |
| 复核 | 谁确认没有抄表达 |

### 4.3 相似度复核（每个阶段 PR 前）

- 随机抽 5 个新增文件，问：
  - 有没有和 ALCOM 相同的注释句/错误句/变量名组合？
  - 有没有"结构一模一样、只是换了语言"的函数？
  - UI 文案是否能在 ALCOM 里搜到同样的句子？
  - 模板/图标/测试数据是否来自 ALCOM？
- 任何一项"是" → 重写，不要辩解"只有这一句"。
- 在 PR 描述里写："净室复核：通过；参考了哪些行为；未复制代码/文案/资产。"

### 4.4 污染处理

1. 立即停止该分支的合并。
2. 在观察日志里记录污染点（哪个文件、哪一段、来自哪里）。
3. 删除并重写，不留"稍后改"。
4. 如果已经合并：开修复 PR，说明范围；必要时回退该 PR。
5. 通知用户，不隐瞒。

## 5. 许可证策略

### 5.1 Atrium 自身

- Atrium 现有许可证保持不变（以仓库根 `LICENSE` 为准）。
- 新增的 Atrium 源代码由你（项目所有者）享有著作权；贡献者需有相应授权。
- 不把 ALCOM/vrc-get 的 MPL/其他代码混入；否则会改变整个文件的许可义务。

### 5.2 新增依赖允许清单

优先选：

- MIT
- ISC
- Apache-2.0
- BSD-2-Clause / BSD-3-Clause
- 0BSD / CC0（仅限代码/数据，注意专利与商标）

禁止：

- GPL / AGPL / LGPL（除非只是独立的可选外部程序，且不随包分发；本项目不需要）
- MPL/EPL 代码片段混入（可以单独依赖，但不要把代码抄进来）
- 任何 "source-available but no commercial use" / "no derivative" 的许可
- 不明许可证的仓库、脚本、模板、图标

建议新增（按需）：

- `semver`（ISC）：版本/范围解析。VPM 选择语义仍由我们实现。
- `yazl`（MIT）：工程备份 zip 写入。读取已有 `yauzl`。
- 其余尽量用 Electron/Node 自带能力，避免"为了一个小功能加一个大包"。

每个新增依赖都要：

1. 在 PR 里说明为什么需要、体积、替代方案；
2. 更新 `THIRD-PARTY-NOTICES`（许可证、版本、来源）；
3. 确认不包含禁止许可；
4. 不把它的示例代码整段复制进产品。

### 5.3 VRChat / 第三方包

- 不随安装器分发 VRChat SDK、付费模型、贴图、服装、Booth 资源。
- 运行时从官方仓库下载的包，其许可证归包作者/VRChat；用户需自行遵守。
- UI 里要有"包可能包含会在 Unity 中执行的编辑器脚本，请只添加可信仓库"的提示。
- 仓库元数据（名称、描述、图标）由仓库提供，运行时获取；我们不把它打包进安装器。
- 导入用户模板/包时，保留其原始许可文件（如有），不改写。

## 6. 命名与商标

| 名称 | 用法 |
|---|---|
| Atrium / 素材管家 | 我们的产品名；继续使用 |
| VPM | 事实性协议名；可以说"VPM 项目/包" |
| VCC | 事实性兼容对象；可以说"从 VCC 导入设置" |
| ALCOM / vrc-get | 只在兼容性说明/开发文档中事实性提及；不做功能名、不放在主界面标题 |
| VRChat | 事实性平台名；不暗示官方背书 |
| 官方仓库 / curated | 事实性描述；不把仓库内容说成我们的 |

- 不使用 ALCOM 的 logo、图标、启动图、安装器图标。
- 不注册/占用 `vcc://` 作为默认协议（除非用户显式选择）；Atrium 自己的协议用 `atrium://`。
- 导出模板用我们自己的扩展名（建议 `.atriumtemplate`）；`.alcomtemplate` 只做**导入**兼容，
  不在 UI 里宣称"ALCOM 官方模板"。

## 7. 每次 PR 的净室检查表

复制到 PR 描述里逐条勾：

```text
[ ] 本次实现只依据行为规格/公开协议/Atrium 代码，没有对照 ALCOM 源码逐行写
[ ] 没有复制 ALCOM 的代码、注释、测试、夹具、错误文案、日志格式
[ ] 没有复制 ALCOM 的 UI 文案、图标、模板、截图、语言文件
[ ] 新增依赖均为宽松许可，已更新 THIRD-PARTY-NOTICES
[ ] 没有引入 vrc-get 的 crate/二进制/npm 包
[ ] 没有把 VRChat SDK/第三方包/用户数据提交进仓库
[ ] 随机抽查 5 个新增文件，未发现"换语言的同一段实现"
[ ] 观察日志已更新（来源、观察、落地、复核）
[ ] 如有污染怀疑，已停止并重写/上报
```
