# Unity 物品封面

将素材包或 Unity 工程里的模型拍成图片，显示在 Atrium 素材卡片上。适用于没有商品预览图的道具、服装、模型和合集成员。此功能属于 main 的后续更新，v0.4.1 发布包尚未包含。

## 使用

### 直接预览素材包

1. 打开素材详情，点击「编辑封面」，使用默认的「从素材包预览」。支持原始 unitypackage、含 unitypackage 的 ZIP，以及包含 unitypackage 的素材目录。
2. Atrium 自动寻找本机 Unity 2022.3；未找到时，点击「选择 Unity 编辑器」，选择安装目录中的 `Editor/Unity.exe`。需要可用的 Unity 安装、本机许可证和 GPU，工程无需提前打开。
3. Atrium 先检查已连接工程中的 lilToon。此前保存过的素材沿用原依赖；新素材优先使用上次成功保存的选择，否则仅有一个可用工程时会推荐它。下拉框显示工程名、lilToon 版本及不可用状态，可改选或选择不使用外部依赖。此处只读取 `Packages/jp.lilxyzw.liltoon` 中的渲染资源，工程无需运行；不会为了检查依赖启动 Unity。
4. 等待读取素材、启动独立 Unity 和生成候选图片。界面显示当前阶段及已用时间，第一次需要导入资源，耗时较长；可以取消查找或关闭窗口。预制体优先展示，并与原始模型分别标注。先显示 8 项，最多 50 项，可点击「显示更多物品」，也可按名称、资源路径或包内来源搜索，筛选预制体或原始模型。
5. 点击要使用的图片，按需要调整角度和深浅背景，确认后点击「保存封面」。查找和生成图片不改变原封面。

预览工程位于应用数据目录中的 `cover-previews`，不会出现在工程列表，也不会成为导入目标。素材包及依赖工程保持原位；预览不向改模工程导入素材、不安装桥接，不产生素材导入记录。应用每次保留至多三个已准备的预览工程；退出时停止自有进程并尝试清理，未能清理的缓存在后续预览前清理，仍在运行的预览进程使用的目录保留。闲置五分钟后关闭预览 Unity。

模型、材质、贴图和渲染依赖会复制到独立工程；供应方脚本、插件和程序集不复制。依赖缺失、资源冲突或不支持的内容会显示提示，保留原封面。没有 Unity 时仍可选择本地图片。

### 从已有 Unity 工程拍摄

1. 打开包含该物品的 Unity 工程，等待编译和资源导入完成，退出播放模式。
2. 在 Atrium 打开素材详情，点击「编辑封面」，选择「从 Unity 工程预览」和该 Unity 工程。自动查找要求桥接 1.2.0 或以后；旧桥接显示「更新桥接」，更新后等待 Unity 完成编译。
3. 首次设置时，Atrium 读取这份素材的资源清单，查找所选工程中对应的预制体和模型，逐张生成候选图片。手动导入 Unity 的物品也能通过原素材的 ZIP 或 unitypackage 清单匹配。先显示 8 项，可点击「显示更多物品」。
4. 点击要使用的候选图片。预制体优先展示；多个款式及原始模型都会保留供你确认，可搜索或按类型筛选，包内成员路径帮助区分来源。选择角度及深色或浅色背景会重新拍摄。
5. 确认预览内容后点击「保存封面」。查找和生成候选图片不会更改卡片；取消、失败及过期预览保留原封面。已关联的素材记住原对象；需要更换时点击「重新查找物品」。

没有找到对应物品时，可在 Unity 的层级或 Project 面板选中物品，点击「读取 Unity 当前选中物品」，或搜索已导入的预制体和模型，再点击「生成预览」。手动选择仍可使用桥接 1.1.1。自动查找依据资源 GUID，不按名称猜选，也不把尚未导入的物品安装进工程；资源换过 GUID 或缺少可读取的原文件时，手动选择仍可设置封面。

需要拍巧克力盒，就选巧克力盒所在的对象；选择整个角色会把整个角色一起拍进去。一个包可以关联其中一个预制体作为封面。方向预设使用世界方向；有些预制体是平放建模的，「下方」可能才是装饰面。也可以在 Unity Scene 窗口转到合适的视角，再使用「Unity 当前视角」；该选项复用视角方向并自动重新取景。

「选择本地图片」支持 PNG、JPEG、WebP、BMP，文件最多 8 MB，无需 Unity 在线。「恢复原始封面」移除自定义封面，恢复第一次覆盖前的图片或无图状态。已有图片存储在素材目录时，覆盖前会缓存原图，之后移动素材不会影响恢复。

如果原始图片无法读取、解码或备份，本次覆盖不会保存。检查原图及缓存目录后重试，避免丢失可恢复的原封面。

选中多张卡片，点击「更新所选封面」。任务按照已保存的来源、对象、角度和背景串行更新，显示每张素材的名称及结果。素材包封面记住资源 GUID 及依赖工程，重启后从原包重建；原包仍需可读取。手动图片、尚未关联的物品和未保存到场景的临时对象会跳过。取消会停止后续任务；已经完成的更新保留，当前未确认结果不会应用。更新期间改成手动图片时，批量任务会保留你的新选择。

## 支持范围

- 验证环境为 Unity 2022.3.22f1、Built-in 渲染管线，包括 lilToon 2.3.4 的巧克力道具。
- 支持 MeshRenderer 和 SkinnedMeshRenderer；后者冻结编辑器当前骨骼及 BlendShape 姿态。隐藏的子物体不参与拍摄，LOD 使用第一层网格。
- 不运行道具脚本、Animator、MA/NDMF 构建或 VRChat 交互逻辑，因此封面不是游戏内效果验证。特殊依赖场景灯光、外部对象或后处理的材质，画面可能与场景不同。
- 素材包模式支持 ZIP / unitypackage 的静态 Built-in 资源，外部 shader 首版支持本机工程中的 lilToon；URP/HDRP、粒子、动画和自动下载依赖尚未支持。工程模式要求物品已导入且可正常显示。
- 素材包模式只复制经过类型识别的网格、纹理等 YAML `.asset`；二进制和未知 `.asset` 显示略过提示。独立模型文件、RAR、7z、加密和嵌套压缩包暂需先整理为受支持的包，或使用工程模式。原包上限 512 MiB、解压资源 2 GiB，最多 32 个包、20,000 个条目和 10,000 个 GUID，读取截止 45 秒。
- 原包内部的相同资源可归并；原包与所选依赖工程、依赖工程内部存在重复 GUID 时拒绝预览，避免 Unity 自动重分配标识造成错误材质。原包已经自带完整 shader 时，可取消选择依赖工程。
- 自动查找可读取 unitypackage、ZIP 内的 unitypackage，以及素材目录中的包清单；同时使用该素材在所选工程里的成功导入记录。RAR、7z、嵌套压缩包和无法读取的加密成员需要手动选择。查询有文件、时间和条目上限，结果不完整时会明确提示。
- 合集里的成员卡片仅查找该成员的资源。同名包或相同目录名存在多个匹配、无法确认归属时，会提示改用手动选择，避免混入其他成员的物品。
- 同一个包的不同预制体和 FBX 均可成为候选；最多返回 50 个物品。候选表示资源已存在且有可绘制网格，材质或 shader 仍可能在生成图片时失败。场景中修改过的姿态、材质和装备组合可继续通过「读取 Unity 当前选中物品」拍摄。
- 复杂对象设有 500 个渲染器、200 万顶点上限，请优先选择具体物品。

生成使用独立预览场景，直接绘制网格及材质副本，不实例化源对象脚本，不保存或更改源场景。Unity 输出 640×480 PNG，Atrium 解码为最长边 320 像素的 JPEG 缓存，每次保存使用独立地址。封面关联保存在数据库中，重启后可以继续更新。手动数据库备份包含关联记录，但不包含封面图片缓存。

## 常见问题

**生成按钮不可点：** 确认已经选择工程及物品，Unity 已退出播放模式、完成编译和导入，且桥接已更新。多个候选需要明确选择一个。

**物品找不到：** 选中的物品可能已删除，场景尚未保存，或切换了工程。重新读取选择或搜索并关联。没有保存到场景的对象仅能用于本次生成，保存场景后重新关联即可用于批量更新。

**自动查找没有结果：** 确认选中的工程已经导入这份素材，且素材原文件仍可读取。没有导入日志时，Atrium 可通过 ZIP / unitypackage 的资源标识匹配；文件已丢失、资源标识改变或格式暂不支持时，使用手动选择或搜索。查找可以取消，关闭窗口或切换工程后返回的旧结果不会保存。

**缺少模型、材质或着色器：** 先在 Unity 修复物品本身，再生成封面。失败时可展开「查看错误详情」，检查具体错误和桥接栈信息。

**素材包图片提示缺少着色器：** 使用 lilToon 的物品可选择含该包的依赖工程。原包自带 shader 时可不选依赖。其他 shader 依赖需先在已有工程中配置，再使用工程模式；失败不会用错误的替代材质保存。

**依赖工程不可用：** 已保存的依赖被移走、删除或无法读取时，会保留原选择并提示更换。修复工程后点击「刷新依赖」，或选择其他可用工程。生成预览、失败、取消和选择本地图片都不改变全局记忆；只有成功保存素材包封面才更新下次使用的依赖。

**查找或生成失败：** 提示会说明下一步操作，可重试查找、重试当前预览或单独重试失败的候选图片。错误详情默认折叠。阶段及用时表示实际运行状态，不提供未经测量的完成百分比或剩余时间。预制体通常带有作者配置的材质，原始模型可能尚未配好材质；优先检查预制体，仍由你确认画面后保存。

**预览未保存或提示封面已变化：** 预览有效期为 10 分钟。生成期间封面被其他操作修改时，不会覆盖最新选择；重新打开编辑窗口确认后再保存。

## 开发验证

自动测试覆盖保存/恢复、同哈希卡片独立封面、原图缓存、异步缩略图竞争、原图引用清理、旧桥接、路径和目录链接拒绝、取消及晚到响应、预览过期、批量保护和错误详情。

`tools/verify-unity-preview.cs` 在隔离 Unity 工程验证真实 GPU 渲染、颜色、尺寸、SkinnedMesh 和材质属性块，以及源材质/选择/场景状态与资源清理。需要自备合法的巧克力资源副本及 shader；第三方素材不随仓库提交。

测试还覆盖没有骨骼、只带 BlendShape 的网格，验证烘焙后重新计算临时网格包围盒。可将合法的百奇资源副本放在测试工程 `Assets/Stick/`，额外验证该模型；没有这份可选资源时，合成回归仍会执行，百奇样例明确跳过。

`tools/verify-cover-ui.cjs` 在隔离应用目录运行实际 Electron 界面、IPC 和数据库，验证预览、保存、取消、本地图片、恢复、批量保护及重启。默认测试工程为 `tmp/cover-verification/unity-sandbox`；可通过 `AVCA_COVER_TEST_PROJECT` 指定带验证夹具的其他测试工程。运行前执行 `npm run native:electron`、`npx electron-vite build`，并让测试 Unity 执行 `AtriumPreviewVerification.Serve`。设置 `ATRIUM_COVER_DEV_URL` 可连接 Vite 开发页面，验证 React StrictMode；使用开发页面时仍需已构建的主进程和 preload。

自动候选的界面及取消回归可设置 `ATRIUM_COVER_CANDIDATES_ONLY=1` 运行；此模式使用实际界面、preload、IPC 与隔离数据库，控制外部 Unity 响应，不证明真实渲染。另加 `ATRIUM_COVER_SAVE_RACE_ONLY=1` 验证保存过程中控件锁定及排队预览清理。

真实原包验收设置 `ATRIUM_COVER_LIVE_CANDIDATES=1` 和 `ATRIUM_COVER_SAMPLE_SOURCES=<JSON 路径>`。JSON 与合法资源副本必须位于忽略的 `tmp/cover-verification/` 下，每项包含 `name`、`source`、`library` 与 `expectedPath`（测试工程的 `Assets/` 路径）。此模式从原 ZIP 读取资源标识，用实际 Unity 生成图片，再通过实际界面选择及保存；不依赖预存导入记录或资源清单。第三方资源与测试产物不进入 Git。

未导入素材的实际渲染检查使用 `tools/verify-package-preview.cjs`，需要 Node 原生依赖及 `ATRIUM_PACKAGE_EDITOR`。`tools/verify-package-cover-integration.cjs` 使用已构建 Electron 应用和 Electron 原生依赖，验证实际界面、独立 Unity、保存、恢复、批量及重启。两者读取忽略的 `tmp/cover-verification/actual-sample-clones.json` 和合法的 shader 工程副本；模型仅从 ZIP 放入新建的预览工程。`tools/verify-package-cover-ui.cjs` 使用受控外部响应验证 React 的取消、模式切换和保存锁定，不代替实际渲染验收。

`tools/verify-cover-usability-ui.cjs` 在隔离 Electron 组件夹具中验证依赖检查先于查找、推荐及手动改选、预制体排序、搜索及类型筛选、用时、失败重试，以及切换筛选、选项和关闭时的晚到响应。该夹具不启动 Unity，不代替上一项的实际包渲染验收。依赖探测和保存后记忆另有数据库及文件系统回归测试。
