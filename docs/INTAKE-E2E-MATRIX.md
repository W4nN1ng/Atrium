# 摄取端到端矩阵（M9）

测试入口为 `tests/intake/e2e-*.spec.ts`，共 45 条。`tests/helpers/intake-workers.ts` 每次从当前源码编译计划、执行和健康 worker，不使用旧 `out/` 或安装目录。计划由真实 `worker_threads` 返回，主线程按应用协议保存计划及缓存引用，再启动真实执行 worker，检查文件、完整内容身份、数据库引用、来源、进度和撤销。

容量/预算/取消通过已有 IO 钩子在额外的故障注入 worker 中控制，文件、容器、闭包、匹配、计划、执行和数据库仍是真实实现。避免实际占满用户磁盘。Unity 编辑器以协议适配器代替，其余解析、找包、预检和历史编排保持真实。

另有 `tests/renderer/ingest-queue-late-results.spec.ts` 六条界面状态回归：查询与推送之间、推送与推送之间，以及多个查询之间乱序时均应用最新快照；旧快照不能恢复已移除任务；真实较新的取消/续跑仍可改变状态。安装版验收会实际点击确认，并检查嵌套分批来源恢复、最终分类和取消规划后的缓存清理。

## R19 的实际处理

整层展开无法放入缓存时，尚未发布的尝试只释放自己的引用，改用成员队列：先散文件和小容器，再按成员大小处理。每个成员仍完整校验 size/CRC32/SHA-256；规划后回收临时字节，在 `MemberSource` 中保存外层原包 SHA-256 和逐层成员序号、原名、键、SHA-256。确认后按操作恢复所需成员，先完成校验、发布和进度持久化，再回收临时成员。原始来源变化会阻断执行。

临时/目标空间暂时不足时等待并自动继续，仍可取消。其它活动计划持有的缓存不会被回收；持久引用可跨进程重启保留。未持久化的取消尝试在 worker 停止后只清理自己的引用。单个成员或嵌套工作集本身超过预算时，继续原包保留并明确诊断，不能声称已完成规范化展开。

## 验证边界

- 真实私有夹具仅使用 M0 批准的 63 个副本，通过 `AVCA_INTAKE_FIXTURES` 显式启用；缺少该环境时真实副本用例条件跳过，不计通过。
- 1 GiB 复核使用真实文件与压缩包。7.24 GiB 私有 7z 没有额外复制，预算边界用真实合成 7z 配缩小预算验证，不能冒称巨型私包实测。
- 备份重复使用合成完整副本；真实 364 文件备份及全 `E:\vrc` dry-run 留给 M10。
- 本阶段不启动真实 Unity 编辑器，不将协议适配器回放称为编辑器验收。
- 实际测试数量、构建、安装版确认和保护核验结果见本轮交付报告及 `docs/INTAKE-ARCHITECTURE.md`。
