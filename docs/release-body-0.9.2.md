**Atrium 是面向 VRChat 创作者的本地素材管理工具。** 在一个 Windows 桌面应用中完成素材收集、分类检索和 Unity 导入，便于管理模型、服装、贴图与插件。

**v0.9.2 修复“导入一整个文件夹后封面一张都不出”的问题，压缩包素材现在会从包里取封面。**

[下载安装版](https://github.com/W4nN1ng/Atrium/releases/download/v0.9.2/Atrium-Setup-0.9.2.exe) · [下载便携版](https://github.com/W4nN1ng/Atrium/releases/download/v0.9.2/Atrium-portable-0.9.2.exe) · [使用与开发文档](https://github.com/W4nN1ng/Atrium)

> 这是 v0.9.1 的修复版本。完整功能见 [v0.9.0 发布说明](https://github.com/W4nN1ng/Atrium/releases/tag/v0.9.0)。

## 本次更新

### 导入整个文件夹后，封面会正常出现

- **一次导入多个素材也会逐个出封面：** 以前选中一整个文件夹导入时，只有第一个素材会去生成封面，其余都会停在空白方块，关掉应用重开也不会变。现在这一批里的每一个都会去取封面。
- **压缩包素材会打开包取图：** 素材是 `.unitypackage`、`.zip`、`.rar` 时，以前是直接把压缩包当图片去解码（必然失败），所以整批都是首字母方块。现在会打开包找自带预览图：`.unitypackage` 取卖家的 `preview.png`，`.zip`/`.rar` 取包里最像封面的一张商品图。
- **包里套包也能取到：** 常见于“一个 zip 里只放了一个 unitypackage”的素材，会再往里看一层。
- **不会再被误判成“这包没图”：** 以前“还没轮到看压缩包”就会被记成“确认没图”，之后永远不再补。这个判断已经修掉，没真正检查过的不会留下记号。
- **之前已经被误判的素材会自动重新取图：** 更新后第一次启动会自动重看一遍被误记的素材，不需要你手动删除重导。

### 关于“确实没有封面”的素材

纯代码类插件（例如网格拆分工具、着色器源码包）本身不带任何图片，这类素材仍然会显示首字母方块 —— 这是正确结果，不是没取到。用户自己选的封面不会被任何自动补齐覆盖。

## 使用说明与已知限制

| 项目 | v0.9.2 的行为 |
| --- | --- |
| 工作范围 | Windows 11 已实测；Windows 10 尚未完成实机验证。 |
| Unity 版本 | 真机验证以 Unity 2022.3.22f1 为准；其他版本只验证了识别与匹配。 |
| 封面来源 | 只读取素材自带的图片（包内预览图、文件夹内的图片）。不联网抓取商品页图片。 |
| 压缩包解压 | 只抽取用于封面的图片，不会把整个压缩包解开；加密包没有密码时取不到封面，仍显示首字母。 |
| 真 Unity 装包/启动/双击导入/旧式迁移 | 仍建议先在沙盒项目里确认；自动化与失败注入不能替代真机。 |
| 项目写入 | 会修改项目的 `Packages/` 和 `vpm-manifest.json`；应用会先预检并保留回滚副本，Unity 正在运行时会拒绝或等待。 |
| 网络 | 只有刷新仓库、下载包、检查更新会联网；关闭网络后仍可浏览已缓存的包。 |
| 数据目录 | 新安装默认 `%APPDATA%\Atrium`；已有安装保留原来的包数据目录。素材库在安装目录之外。 |
| 回退 | 可以用旧安装包覆盖回 v0.9.1；素材库不受影响，项目与包数据会保留。 |
| 代码签名 | 发布包未进行代码签名，Windows 可能显示 SmartScreen 提示。 |

## 数据位置

| 内容 | 默认位置 |
| --- | --- |
| 素材原文件 | 你指定的素材库或原始文件夹 |
| 素材索引、缩略图、日志及导入前备份 | `C:\Users\你的用户名\AppData\Roaming\A` |
| 项目与包数据库、包缓存、回滚区、项目备份 | 新安装默认 `C:\Users\你的用户名\AppData\Roaming\Atrium`；已有安装保留原目录 |
| 本地安装包投放目录 | 项目与包数据目录下的 `updates` |
| 已记住的压缩包密码 | 本地数据库中，以密文存储 |

卸载只移除程序，素材库和应用数据保留在安装目录之外。
