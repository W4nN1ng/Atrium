## 2. 这 4 个未发布提交做了什么

### `6cdd9a9` fix(vpm): 工程包列表显示名、来源与仓库添加

- 工程页包列表读取 `package.json` 的 `displayName`：
  `VRChat SDK - Avatars`、`Gesture Manager`、`lilToon` 等。
- 来源列显示仓库名：`Official` / `Curated` / `bd_` / 自定义仓库；仓库里没有的包显示
  “工程内包”，不再统一写 `embedded`。
- “最新版本”跟随预发布偏好；未开启预发布时不会被 `3.10.6-beta.2` 顶掉。
- 兼容 ALCOM/VCC 的 `vpm-manifest.json` 对象式依赖
  `"name": { "version": "..." }`；写回保持原格式。
- 状态同时参考 `manifest.locked`，`VRChat SDK - Base` 等传递依赖不再显示“未列出”。
- 工程包管理新增 **添加软件包**：搜索仓库、选版本，进入现有变更预览，不直接写工程。
- 主要文件：
  `src/shared/vpm/domain/project.ts`、`manifest.ts`、`src/main/vpm/ipc/install.ts`、
  `VpmAddPackageDialog.tsx`、`VpmPackagesPanel.tsx`、`lib/cart.ts`。

### `7d97f97` fix(project): 启动先清上一会话运行状态，首屏不显示假绿灯

- 现场：重启后 Lime / shinano-Main2 先亮绿灯，不到 1 秒又变灰。
- 根因：`project.is_running` 是上一轮三路探测的缓存；窗口首屏先读数据库，
  异步探测完成后再覆盖。Lime / shinano-Main2 上次退出时留下了 `is_running=1`。
- 修复：`startProjectWatcher` 先把所有 `is_running` 清零，再由三路探测写真实状态。
- 回归：`tests/project/running-wiring.spec.ts` 预置 `is_running=1`，启动后必须清成 0。
- 已在安装版实测：Lime / shinano-Main2 灰色，只有真正开着的 shinano-Main4 绿色。

### `163994b` fix(project): 旧资源扫描不再误报“结果不完整”

- 现场：Lime 管理页出现“工程扫描达到上限，结果是部分结果”，路径是
  `Assets/Amatousagi/Lime/Animation/Controller/FX_LipSync_Ctrl`。
- 根因：`readLegacy` 的 Assets 旧资源扫描默认 2000 条目 / 4 层；这不是包列表扫描。
- 修复：提高到 **10000 条目 / 12 层**；旧资源截断不再写入工程页 warnings
  （仍保留 `legacy.truncated` 内部标记）。`Packages/` 超过 500 的真实包列表截断仍会提示。
- 影响边界：旧资源扫描只用于“旧式资源迁移”建议；不影响 VPM 装包/升级/卸载。
- 回归：`tests/vpm/domain/project.spec.ts` 两条（深层目录能扫到且无 warning；
  达到配置上限仍 `truncated=true` 但无 warning）。

### `b00b6f5` fix(library): 首次导入后封面不显示——补拍 + 不把“没落稳”记成没图

- 现场：一次拖入 22 件，入库时只出 1 张封面，其余要重启后由 backfill 补出。
- 两个原因：
  1. 旧 `ensureThumb` 把“目录还没落稳、没读到”记成 `cover_image='none'`，
     而 backfill 只捞 `NULL`，于是永远不会补；
  2. 失败后没有重试。
- 修复：只有真正 `readdirSync` 成功/源是文件才记“看过”；新增
  `scheduleThumbRetry`（约 1.5s / 5s 两次，有上限、可取消、timer unref），
  成功后广播 `data:changed`；批量 backfill 一条没出货时 3 秒后补一轮。
- 新增 `tests/library/thumb-retry.spec.ts`（5 条）。
- 这个提交的 `ingest/api.ts` / `thumbs.ts` 在 `git show --stat` 里看起来很大，
  是 CRLF/LF 行尾差异；语义 diff 约 298 插入 / 11 删除。不要整体重写这两个文件。
